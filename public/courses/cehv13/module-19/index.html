02Container Technology — Docker وKubernetes

ما هو Container؟

حزمة تطبيق/برنامج مع كل تبعياته (Libraries وملفات إعداد وثنائيات) تعمل باستقلالية عن العمليات الأخرى. CaaS يتضمّن Virtualization وإدارة Containers عبر Orchestrators.

بنية Container Technology — الطبقات

الطبقةالوصف
Tier-1: Developer Machinesإنشاء واختبار واعتماد الصور (Images)
Tier-2: Testing & Accreditationالتحقّق والتصديق وتوقيع الصور وإرسالها للـ Registries
Tier-3: Registriesتخزين الصور وتوزيعها على الـ Orchestrators (Docker Hub وAmazon ECR وDTR)
Tier-4: Orchestratorsتحويل الصور لـ Containers ونشر الـ Containers على Hosts
Tier-5: Hostsتشغيل وإدارة الـ Containers وفق تعليمات الـ Orchestrator

04منهجية اختراق Cloud وAWS Hacking

Cloud Hacking Methodology

1
Information Gathering

جمع أكبر قدر من المعلومات عن البنية التحتية Cloud المستهدَفة — Shodan وCensys للكشف عن خدمات Cloud المكشوفة وMasscan لاكتشاف البورتات.

2
Vulnerability Assessment

تقييم نقاط الضعف الأمنية: Misconfigurations وبرمجيات غير مُصحَّحة وثغرات في الشبكة والتطبيقات والخدمات — أدوات: Prowler وCloudSploit.

3
Exploitation

الاستغلال الفعلي للثغرات للحصول على وصول غير مصرَّح أو التحكّم في البنية التحتية — قد يؤدّي لتسرّب بيانات أو تعطّل خدمات أو خسائر مالية.

4
Post-Exploitation

الحفاظ على الوصول وتغطية الآثار والتعمّق في الشبكة — سرقة بيانات والاستعداد لهجمات أعمق. تشمل: Log Manipulation وحذف Credentials المؤقتة وإنشاء Backdoors مخفية.

AWS Hacking — تعداد S3 Buckets

S3 (Simple Storage Service) خدمة تخزين سحابية قابلة للتوسّع. المهاجمون يستغلّون Misconfigurations للوصول للملفات والمجلدات والكائنات المخزَّنة. ترك S3 Bucket مفتوحًا يُتيح تعديل ملفات JavaScript وحقن Malware.

# Docker Remote API
docker -H tcp://:2375 ps

# LXD Privilege Escalation
lxc image import alpine.tar.gz --alias alpine
lxc init alpine privesc -c security.privileged=true
lxc config device add privesc mydevice disk source=/ path=/mnt/root recursive=true
lxc start privesc && lxc exec privesc /bin/sh

هجمات Kubernetes etcd

الـ etcd تخزين Key-Value موزَّع لبيانات Cluster وتفاصيل Service Discovery وAPI Objects — الوصول له يُعادل Root على النظام. يُحدِّد المهاجمون Port 2379 لاكتشاف نقاط الاتصال بالـ Kubernetes.

LXD/LXC Privilege Escalation

لو المستخدم في مجموعة 'lxd' يمكنه إنشاء Container مميَّز وربط نظام ملفات الـ Host به ← Privilege Escalation للـ Root. الأمر المستخدَم: lxc config device add privesc mydevice disk source=/ path=/mnt/root.

  • مراقبة CVEs لـ Container Runtime ومعالجتها فور اكتشافها

  • فحص الصور في Repository دوريًا

أفضل ممارسات أمان Docker

  • تجنّب كشف Docker Daemon Socket (نقطة الدخول الأساسية للـ Docker API)

أفضل ممارسات أمان Kubernetes

  • التحقّق الصحيح من محتوى الملفات ومساراتها في كل مرحلة معالجة
  • استخدام Configuration Methods للمسارات الحسّاسة بدلًا من Hard-coded Paths
  • رفع أخطاء صريحة بعد كل خطوة من العمليات المركّبة
  • استخدام well-tested JSON Libraries وأنواع بنيات صحيحة للتعامل مع Kubernetes APIs
  • عدم استخدام Shell Commands المركّبة بدون تحقّق لأنها تؤثّر على حالة النظام

Zero Trust Networks

نموذج أمان يفترض أن كل مستخدم يحاول الوصول للشبكة غير موثوق بشكل افتراضي ← يتحقّق من كل اتصال قبل السماح بالوصول. يتّبع مبدأ: "Trust no one and validate before providing a cloud service". يُطبِّق تحكّمًا صارمًا في الوصول ويراقب تدفّق حركة الشبكة.

الخلاصة العامة للموديول

الموديول ناقش مفاهيم Cloud Computing (8 خصائص و10+ أنواع خدمات و7 نماذج نشر والـ NIST Reference Architecture وFog/Edge Computing)، وبنية Containers وDocker وKubernetes وServerless، وأكثر من 12 نوع هجوم Cloud (MITC وWrapping وCloud Hopper وCryptojacking وIMDS وCPDoS وCloud Snooper وGolden SAML وLotC)، ومنهجية الاختراق الكاملة مع AWS (S3 Enumeration وIAM Privilege Escalation وIMDS وECR/Docker) وAzure وGCP وContainer Hacking (Docker API وLXD وKubernetes etcd)، وختم بطبقات أمان Cloud وأفضل الممارسات وZero Trust.

$ cat ./module19_summary.txt
  • الفرق الجوهري بين IaaS وPaaS وSaaS هو من يُدير ماذا — IaaS تُدير الـ OS فصاعدًا، SaaS CSP يُدير كل شيء
  • MITC يختلف عن MITM في أنه يستغل خدمات Cloud الشرعية للمزامنة — لا اعتراض للحزم
  • IMDS على 169.254.169.254 هو خطر SSRF رئيسي في AWS — يُتيح استخراج IAM Roles وCloud Keys مباشرةً
  • S3 Misconfigurations هي الثغرة الأكثر شيوعًا في AWS — Bucket مفتوح = ملفات وبيانات اعتماد متاحة للجميع
  • etcd في Kubernetes يُخزِّن كل بيانات الـ Cluster — الوصول لـ Port 2379 = Root Level Access
  • LXD Group Membership يُتيح Privilege Escalation للـ Root عبر Container Privileged مع ربط نظام ملفات الـ Host
  • Zero Trust يفترض إن كل شيء مخترق مسبقًا — "Trust no one and validate before providing a cloud service"

السحابة لا تعني أن البيانات آمنة — تعني أن المسؤولية مُشتركة. S3 Bucket مفتوح بغلطة إعداد واحدة، IAM Role بإذن زائد، IMDS مكشوف لـ SSRF — كل هذا بأمثلة حقيقية أدّت لتسرّبات بيانات ضخمة. الدفاع يبدأ بالـ Least Privilege وينتهي بـ Zero Trust.
