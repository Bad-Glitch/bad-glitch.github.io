01مفاهيم الـ SQL Injection

ما هو الـ SQL Injection؟

الـ SQL (Structured Query Language) لغة نصية يستخدمها سيرفر قاعدة البيانات. أوامره الأساسية: INSERT، SELECT، UPDATE، DELETE.

المبرمجون يستخدمون أوامر SQL تسلسلية مع بارامترات يُوفِّرها العميل، مما يُسهِّل على المهاجم حقن أوامر. الـ SQL Injection تقنية تستغل ثغرات الإدخال غير المعقَّم لتمرير أوامر SQL عبر تطبيق الويب للتنفيذ في قاعدة البيانات الخلفية.

السبب الجوهري

SQL Injection ثغرة في تطبيق الويب وليست في قاعدة البيانات أو الـ Web Server. السبب هو أن التطبيق لا يتحقّق بشكل صحيح من المدخلات قبل تمريرها لجملة SQL.

لماذا يُعدّ SQL Injection خطيرًا؟

UNION SQL Injection

تقنية تدمج استعلامًا مزوَّرًا مع الاستعلام الأصلي. بعد تحديد عدد وأنواع الأعمدة:

sql — union injection example
SELECT Name, Phone, Address FROM Users WHERE Id=1
-- الهجوم:
$id=1 UNION ALL SELECT creditCardNumber,1,1 FROM CreditCardTable
-- النتيجة: يضيف أرقام بطاقات الائتمان لنتيجة الاستعلام الأصلي

Blind SQL Injection — Boolean وHeavy Query

التقنيةالشرح
Boolean Exploitationإرسال جمل True وFalse ومقارنة استجابة الصفحة لاستنتاج نجاح الحقن. مثال: id=67 AND 1=2 → صفحة فارغة = نجاح الحقن
Heavy Queryاستخدام استعلامات ثقيلة تستغرق وقتًا طويلًا بدلًا من دوال التأخير — يُنشئ تأخيرًا زمنيًا بضمّات متعددة على جداول النظام. مثال: AND 1 < SELECT count(*) FROM all_users A, all_users B, all_users C
Double-Blind SQL Injection

هجوم متقدّم بدون أي تغذية راجعة مباشرة (لا Error Messages ولا بيانات). المهاجم يبحث عن مؤشّرات غير مباشرة: تغيّرات في سلوك التطبيق أو أوقات الاستجابة. يستخدم Boolean-based وTime-based Blind SQL Injection.

03منهجية الـ SQL Injection

مرحلة جمع المعلومات

1
التحقّق من الاتصال بقاعدة البيانات

تحديد ما إذا كان تطبيق الويب يتصل بسيرفر قاعدة بيانات للوصول للبيانات.

2
تعداد حقول الإدخال

جمع كل حقول الإدخال والحقول المخفية وطلبات POST التي يمكن استخدامها في صياغة استعلام SQL.

3
حقن كود اختباري

محاولة حقن كود في حقول الإدخال لتوليد خطأ.

4
اختبار الأنواع

محاولة إدخال قيمة نصية حيث تُتوقَّع قيمة رقمية في حقل الإدخال.

5
استخدام UNION

استخدام عامل UNION لدمج نتائج SELECT بيانات إضافية.

6
قراءة رسائل الخطأ

التحقّق من رسائل الخطأ التفصيلية للحصول على معلومات لتنفيذ الهجوم.

Blind SQL Injection — استخراج بيانات المستخدم (Time-based)

sql — blind time-based user extraction
-- فحص طول اسم المستخدم
http://certifiedhacker.com/page.aspx?id=1; IF (LEN(USER)=1) WAITFOR DELAY '00:00:10'--
http://certifiedhacker.com/page.aspx?id=1; IF (LEN(USER)=2) WAITFOR DELAY '00:00:10'--
-- (زيّد الرقم لحد ما الـ DBMS يرجع TRUE)

-- فحص الحرف الأول من اسم المستخدم (a=97, b=98, c=99...)
http://certifiedhacker.com/page.aspx?id=1; IF (ASCII(lower(substring((USER),1,1)))=97) WAITFOR DELAY '00:00:10'--
http://certifiedhacker.com/page.aspx?id=1; IF (ASCII(lower(substring((USER),1,1)))=98) WAITFOR DELAY '00:00:10'--

-- نفس الأسلوب لاسم قاعدة البيانات
http://certifiedhacker.com/page.aspx?id=1; IF (LEN(DB_NAME())=4) WAITFOR DELAY '00:00:10'--
http://certifiedhacker.com/page.aspx?id=1; IF (ASCII(lower(substring((DB_NAME()),1,1)))=97) WAITFOR DELAY '00:00:10'--
-- (لو DB_NAME() = ABCD: a=97, b=98, c=99, d=100 → كلها TRUE)
آلية Time-based

المنطق بسيط: لو الاستعلام صحيح يتأخّر الرد 10 ثواني = TRUE، لو فوري = FALSE. بالتكرار مع كل حرف وكل موضع تقدر تبني اسم المستخدم/قاعدة البيانات حرفًا بحرف.

Second-Order SQL Injection

يحدث لما بيانات الإدخال تُخزَّن في قاعدة البيانات أولًا، ثم تُستخدَم لاحقًا في معالجة استعلام SQL آخر بدون تحقّق أو Parameterized Queries.

1
حقن الإدخال

المهاجم يُرسِل إدخالًا مُصمَّمًا في طلب HTTP — التطبيق يحفظه في قاعدة البيانات ويردّ على الطلب.

2
إرسال طلب ثانٍ

المهاجم يُرسِل طلبًا ثانيًا.

3
تنفيذ الحقن

التطبيق يعالج الطلب الثاني بالإدخال الأول المخزَّن وينفّذ استعلام SQL الخبيث.

4
استلام النتائج

النتائج تُرجَع للمهاجم في الاستجابة على الطلب الثاني إن وُجِدت.

-- جميع قواعد البيانات على السيرفر
' and 1 in (select min(name) from master.dbo.sys.databases where name >'.') --

-- مكان ملفات قواعد البيانات
' and 1 in (select min(filename) from master.dbo.sys.databases where filename >'.') --

-- جداول وأعمدة في استعلام واحد
' union select 0, sys.objects.name + ': ' + sys.columns.name + ': ' + sys.types.name, 1,1,'1',1,1,1,1,1
  from sys.objects, sys.columns, sys.types
  where sys.objects.xtype = 'U'
  AND sys.objects.id = sys.columns.id
  AND sys.columns.xtype = sys.types.xtype --

إنشاء Database Backdoor عبر Trigger

sql — malicious trigger backdoor
-- مثال: Trigger يضبط سعر كل منتج على 0 تلقائيًا
CREATE OR REPLACE TRIGGER SET_PRICE
AFTER INSERT OR UPDATE ON ITEMS
FOR EACH ROW BEGIN
    UPDATE ITEMS SET Price = 0;
END;
خطورة Database Backdoor

الـ Trigger ينفّذ تلقائيًا عند كل INSERT أو UPDATE على الجدول — المهاجم يستطيع التحكّم في البيانات بشكل مستمرّ حتى بعد اكتشاف الاختراق وإزالة الـ Payload الأولي.

DNS Exfiltration عبر SQL Injection

المهاجم يستخدم استعلامات DNS لاستخراج البيانات (مثل Password Hashes). طلبات DNS من السيرفر يمكنها عبور جدار الحماية عبر سيرفر DNS داخلي حتى لو كان الـ Firewall يمنع الإرسال المباشر للإنترنت.

MongoDB / NoSQL Injection

MongoDB يستخدم قاعدة بيانات NoSQL معرَّضة لهجمات NoSQL Injection. التطبيقات التي تستخدمها (PHP وJavaScript وPython وJava) قد تحتوي هذه الثغرة في كود المصادقة — تُتيح تجاوز Authentication وسرقة البيانات وتعديلها. مثال: تطبيق PHP يسمح بعملية $where في MongoDB — المهاجم يحقن كود JavaScript خبيث يعرض قائمة المستخدمين.

06الإجراءات المضادة

أفضل ممارسات منع SQL Injection

  1. لا تفترض أي شيء عن حجم أو نوع أو محتوى البيانات المُستلَمة — دائمًا تحقّق
  2. اختبر حجم ونوع الإدخال وفرض حدودًا مناسبة لمنع Buffer Overflows
  3. اختبر محتوى متغيّرات النصوص واقبل فقط القيم المتوقَّعة
  4. ارفض الإدخالات التي تحتوي بيانات ثنائية أو Escape Sequences أو محارف التعليقات
  5. لا تبنِ جمل Transact-SQL مباشرةً من إدخال المستخدم — استخدم Stored Procedures للتحقّق
  6. طبِّق طبقات متعددة من التحقّق ولا تدمج إدخال المستخدم غير المتحقَّق منه
  7. تجنّب بناء SQL ديناميكي بقيم مُدخَلة متسلسلة (String Concatenation)
  8. استخدم أنواع حسابات SQL الأكثر تقييدًا للتطبيقات (Least Privilege)
  9. تأكّد إن ملفات Web Config لا تحتوي معلومات حسّاسة
  10. نفِّذ اختبار Black Box Injection الآلي وتحليل الكود الثابت والاختبار اليدوي
  11. احتفِظ بالبيانات غير الموثوقة منفصلة عن الأوامر والاستعلامات
  12. في غياب Parameterized API استخدم Escape Syntax خاصة بالمفسِّر لإزالة الأحرف الخاصة
  13. استخدم خوارزمية Hash آمنة مثل SHA256 لتخزين كلمات مرور المستخدمين (لا تخزّن Plaintext)
  14. استخدم Data Access Abstraction Layer لتطبيق وصول آمن للبيانات في كل التطبيق
  15. صمِّم الكود بحيث يلتقط ويعالج الاستثناءات بشكل مناسب
  16. أزِل رسائل Code Tracing وDebug قبل نشر التطبيق
  17. طبِّق قواعد Least Privilege لتشغيل التطبيقات التي تصل لـ DBMS
  18. احذف الحسابات الافتراضية من قاعدة بيانات SQL
  19. استخدم ORM Frameworks مثل Hibernate وSpring Data JPA — توفّر آليات مدمَجة لبناء وتنفيذ استعلامات SQL بأمان مع Parameterization تلقائي

الخلاصة العامة للموديول

الموديول ناقش مفاهيم SQL Injection وأسبابه، وأنواعه الثلاثة الرئيسية (In-band وBlind وOut-of-Band) مع أنواعها الفرعية، ومنهجية الهجوم الكاملة (جمع المعلومات، اكتشاف الثغرات، تنفيذ Union وBlind وOut-of-Band)، والـ Advanced SQL Injection (تعداد قاعدة البيانات ونقلها والتفاعل مع OS وإنشاء Backdoors وDNS Exfiltration وNoSQL Injection)، ثم تقنيات تجاوز الـ WAF والإجراءات المضادة والأدوات.

$ cat ./module15_summary.txt
  • SQL Injection ثغرة في التطبيق لا في قاعدة البيانات — السبب الجوهري هو عدم التحقّق من الإدخال قبل تمريره لجملة SQL
  • In-band = نتائج في نفس القناة (الأسرع)، Blind = نتائج True/False أو تأخير زمني (الأبطأ)، Out-of-Band = قناة مختلفة (DNS أو HTTP)
  • Tautology (OR 1=1) لتجاوز المصادقة — Piggybacked Query (;) لتنفيذ استعلام إضافي — End-of-Line Comment (--) لإلغاء بقية الاستعلام
  • Time-based Blind يكشف البيانات حرفًا بحرف عبر WAITFOR DELAY — يتطلّب وقتًا طويلًا لكنه ينجح حتى مع أكثر التطبيقات صمتًا
  • Advanced SQL Injection يتجاوز قاعدة البيانات للـ OS: LOAD_FILE/OUTFILE في MySQL وxp_cmdshell في MSSQL
  • الدفاع الأساسي: Parameterized Queries (Prepared Statements)، Stored Procedures، ORM Frameworks، والتحقّق الصارم من الإدخال في كل طبقة

SQL Injection ليس مجرّد سرقة بيانات — هو في أسوأ أحواله مفتاح لنظام التشغيل كله. من UNION SELECT للحصول على الأعمدة، لـ INTO OUTFILE لزرع PHP Shell، لـ xp_cmdshell لتشغيل أوامر OS، لـ Reverse Shell للسيطرة الكاملة — كل هذا يبدأ من مدخل واحد غير مُتحقَّق منه.

Exam Tip

أسئلة هذا الموديول تُركِّز على: الفرق بين In-band وBlind وOut-of-Band، الفرق بين Boolean وTime-based Blind SQL Injection، الفرق بين Piggybacked Query وTautology وEnd-of-Line Comment، آلية Second-Order SQL Injection، كيف تستخدم LOAD_FILE() وINTO OUTFILE() وxp_cmdshell، وتقنيات تجاوز WAF (Char Encoding وIn-line Comments وNull Byte).
