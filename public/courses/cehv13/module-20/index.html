أهداف Cryptography (CIA + N)

الهدفالشرح

أنواع Cryptography

الخوارزميةنوعهاحجم المفتاححجم الكتلةملاحظات

3DESBlock Cipher168-bit (3×56)64-bitDES×3 بثلاثة مفاتيح (K1 وK2 وK3): Encrypt-K1 → Decrypt-K2 → Encrypt-K3. الخيار الأول (3 مفاتيح مختلفة) هو الأكثر أمانًا

خوارزميات Asymmetric Encryption

الخوارزميةالشرح
DSA (Digital Signature Algorithm)FIPS للتوقيعات الرقمية — ينشئ توقيعًا رقميًا 320-bit بأمان 512-1024-bit. Private Key للتوقيع، Public Key للتحقّق. أقل احتمالية للتزوير من التوقيع الخطّي
RSAنظام تشفير بالمفتاح العام — يستخدم حساب المعيار (Modular Arithmetic) وعددَين أوليَّين كبيرَين. معيار De-facto للتشفير والتوثيق على الإنترنت. يُستخدَم في Windows وApple وSun وNovell وبطاقات Ethernet الذكية والهواتف الآمنة
Diffie-Hellmanبروتوكول تشفير يُتيح لطرفَين إنشاء مفتاح مشترك عبر قناة غير آمنة — نُشِر عام 1976 من Whitfield Diffie وMartin Hellman
ECCنظام تشفير بالمفتاح العام يستخدم المنحنيات الإهليلجية لتوليد مفاتيح أقصر وأسرع وأكثر أمانًا من RSA — مقترَح كبديل لـ RSA لتقليل حجم المفتاح
YAKبروتوكول Authenticated Key Exchange (AKE) — مشتقّ من HMQV مع Zero-Knowledge Proofs (ZKP). يوفّر Private Key Security وFull Forward Secrecy وSession Key Security

دوال Hash (Message Digest)

تحسب تمثيلًا فريدًا ثابت الحجم (128-256 bit) لأي كتلة من المعلومات. تغيير أي bit في الإدخال يُعطي 50% احتمال تغيّر كل bit في الإخراج. تُسمّى One-way لأن عكس العملية شبه مستحيل. لا تشارك في التشفير وفكّ التشفير مباشرةً.

Hash Functionحجم الإخراجملاحظات
MD5128-bitسريع لكن عُثِر على Collisions — لا يُوصَى به للأمان الحرج
SHA-1160-bitطوّره NIST — أبطأ قليلًا من MD5 لكن أكثر أمانًا. عُثِر على Collisions نظريًا
SHA-2 (SHA-256/512)256 أو 512-bitNIST FIPS PUB 180 — Secure Hash Standard (SHS). الأكثر استخدامًا حاليًا
SHA-3متغيّرمختلف بنيويًا عن SHA-2 — بُني على Keccak Algorithm
RIPEMD-160160-bit160/128/256/320-bit variants — طوّره Dobbertin وBosselaers وPreneel. لا يتبع معايير أمنية قياسية محدَّدة
HMACمساوٍ للـ Hash المُضمَّنHash-based MAC يستخدم مفتاحًا تشفيريًا مع Hash Function (SHA-1 أو MD5). مرحلتان: Inner Hash ثم Outer Hash
GOST Hash256-bitمعيار روسي GOST R 34.11-94 — كتل 256-bit مع Padding للمساواة

Multilayer Hashing

تقنية تطبّق Hash Function عدّة مرّات على الإدخال أو الإخراج السابق — تُعزِّز الأمان وتُنشئ هياكل Hash أكثر تعقيدًا. الخطوات: Initial Hashing ← Subsequent Hashing ← Final Hash Value. أداة: CyberChef.

أوضاع عمل Block Cipher

الوضعالشرح
ECB (Electronic Code Book)أبسط وضع — يُقسِّم النص إلى كتل ويشفِّر كل كتلة باستقلالية بنفس المفتاح. ضعيف: نفس Plaintext ينتج نفس Ciphertext
CBC (Cipher Block Chaining)تحسين لـ ECB — كل كتلة تُخضَع لـ XOR مع Ciphertext الكتلة السابقة قبل التشفير. الكتلة الأولى تستخدم Initialization Vector (IV)
CFB (Cipher Feedback)الـ Ciphertext السابق يُستخدَم كـ Feedback للخوارزمية — IV في Shift Register ← XOR مع Plaintext
Counter Modeيستخدم Counter Value كإدخال للخوارزمية مع المفتاح ← XOR مع كتلة Plaintext. يسمح بالمعالجة المتوازية

Authenticated Encryption (AE) Modes

الوضعالشرح
Encrypt-then-MAC (EtM)تشفير أولًا ← إنشاء MAC للـ Ciphertext ← إرسالهما معًا. الأعلى أمانًا بين أوضاع AE
Encrypt-and-MAC (E&M)إنشاء MAC للـ Plaintext + تشفير Plaintext ← إرسال Ciphertext وMAC معًا
MAC-then-Encrypt (MtE)إنشاء MAC للـ Plaintext ← دمجه مع Plaintext ← تشفير المجموع. الـ Ciphertext يحتوي MAC مشفَّرًا
AEADإضافة Associated Data للـ Ciphertext — يُتيح رأس الرسالة غير مشفَّر للتحقّق من المصدر، والـ Payload مشفَّر للسرية. يمنع Chosen Ciphertext Attacks

Hardware-Based Encryption

الجهازالشرح
TPM (Trusted Platform Module)رقاقة Crypto-processor في اللوحة الأم — تخزين آمن للمفاتيح، Full Disk Encryption، تخزين كلمات المرور، حماية الترخيص، التحقّق من سلامة المنصّة
HSM (Hardware Security Module)جهاز أمان خارجي إضافي للـ Crypto-processing — إدارة وتوليد وتخزين مفاتيح تشفيرية. يُوفِّر تشفيرًا مُحسَّنًا لمفاتيح Symmetric أطول من 256-bit. High-performance HSMs عبر TCP/IP
USB Encryptionتشفير داخلي على أجهزة USB — حماية ضد توزيع Malware عبر USB ومنع تسرّب البيانات
Hard Drive Encryptionتشفير كل البيانات المخزَّنة على القرص — يستخدم TPM أو HSM (لا يدعم Keyboard أو Fingerprint)
Quantum Cryptography

تشفير مبني على ميكانيكا الكم (QKD). البيانات مُشفَّرة بفوتونات ذات خاصية دوران تتغيّر أثناء مرورها عبر الفلاتر. المهاجمون لا يستطيعون التلاعب في البيانات لأن الفوتونات تُنقَل عبر فلاتر عشوائية.

02تطبيقات Cryptography — PKI وPGP وBlockchain

Public Key Infrastructure (PKI)

مجموعة من العتاد والبرمجيات والسياسات والإجراءات اللازمة لإنشاء وإدارة وتوزيع واستخدام وتخزين وإبطال الشهادات الرقمية.

المكوّنالشرح
Certificate Authority (CA)كيانات موثوقة تُصدِر الشهادات الرقمية — تُؤكِّد امتلاك صاحب الشهادة للمفتاح العام. أمثلة: Comodo وIdenTrust
Signed Certificateشهادة من CA موثوق — تحتوي: اسم الحامل وRSerial Number وتواريخ الصلاحية ونسخة المفتاح العام وتوقيع CA الرقمي
Self-Signed Certificateمستخدم يُنشئ شهادته الخاصة (Adobe Acrobat أو Java keytool أو Apple Keychain) — التحقّق يرجع للمستخدم نفسه وليس CA

Digital Signatures

تستخدم Asymmetric Cryptography لمحاكاة خصائص أمان التوقيع في الشكل الرقمي. يُمكن تعزيز أمانها بتشفير الإيميل الموقَّع. RSA هو أول تقنية تُولِّد توقيعات رقمية.

عملية DSAالشرح
Signature GenerationPrivate Key يُحدِّد هوية الموقِّع ← يُولِّد توقيعًا 320-bit
Signature VerificationPublic Key يتحقّق من صحة التوقيع الرقمي

SSL وTLS

البروتوكولالشرح
SSL (Secure Sockets Layer)بروتوكول طبقة تطبيق من Netscape لتأمين نقل الرسائل عبر الإنترنت — يستخدم RSA لتشفير البيانات
TLS (Transport Layer Security)بروتوكول لإنشاء اتصال آمن بين العميل والسيرفر مع ضمان الخصوصية والتكامل. TLS Handshake: مصادقة متبادلة + اختيار خوارزمية + تبادل Symmetric Key. TLS Record: اتصالات مُؤمَّنة بـ DES وغيره

Pretty Good Privacy (PGP)

بروتوكول لتشفير/فكّ تشفير البيانات مع مصادقة وخصوصية — يُستخدَم لضغط البيانات والتوقيع الرقمي وتشفير الرسائل والملفات والإيميلات.

العمليةالآلية
PGP Encryption1. ضغط البيانات (يُقلِّل الأنماط التي تُستغَل في Cryptanalysis). 2. توليد Random Key مؤقّت. 3. تشفير Plaintext بالـ Random Key (IDEA). 4. تشفير الـ Random Key بالمفتاح العام للمستقبِل (RSA). 5. إرسال Ciphertext + Random Key المشفَّر معًا
PGP Decryption1. فكّ تشفير الـ Random Key بالمفتاح الخاص (RSA). 2. فكّ تشفير Ciphertext بالـ Random Key المُستردّ
مكوّنات PGP

RSA لنقل المفاتيح وIDEA لتشفير الرسائل الضخمة. RSA لحساب التوقيعات الرقمية. MD5 لحساب Message Digests.

GPG (GNU Privacy Guard)

بديل مجاني لـ PGP يُنفِّذ معيار OpenPGP. Hybrid Encryption: Symmetric للسرعة + Asymmetric لتبادل المفاتيح. يدعم: إدارة المفاتيح، التوقيع وفكّ التشفير، Detached Signatures، رفع المفاتيح لـ Key Servers.

Web of Trust (WoT)

نموذج ثقة في PGP وOpenPGP وGnuPG — كل شخص في الشبكة يعمل كـ CA ويُوقِّع على بيانات هوية الأشخاص الذين يثق بهم. كل مستخدم لديه Ring من المفاتيح العامة للتشفير.

Blockchain

نوع من Distributed Ledger Technology (DLT) يُسجِّل ويُخزِّن تاريخ المعاملات في كتل مرتبطة تشفيريًا ببعضها. البيانات مقاومة للتعديل.

نوع Blockchainالشرحمثال
Public (Public Ledger)لا سلطة مركزية — شبكة لا مركزية مفتوحة للجميع — لا يمكن تعديل البيانات بعد التحقّقBitcoin وEthereum
Private (Private Ledger)سلطة مركزية تُقرِّر من يشارك — فقط المشاركون في المعاملة يعلمون بهاHyperledger وRipple (XRP)
Federated / Consortiumلامركزية جزئية — مجموعة أفراد أو مؤسسات تُنشئ وتُدير شبكات منفصلة — سريعة وقابلة للتوسّعEWF (Energy) وR3 (Banks)
Hybridمزيج من Public وPrivate — بيانات مختارة متاحة للعموم والباقي سرّيIBM Food Trust

03Cryptanalysis — طرق التحليل وهجمات التشفير

طرق Cryptanalysis

الطريقةالشرح
Linear Cryptanalysisإيجاد تقريبات خطية لعمل Block Cipher — Known Plaintext Attack يستخدم تقريبًا خطيًا لوصف سلوك الـ Cipher. ابتكرها Mitsuru Matsui
Differential Cryptanalysisدراسة الفروق في الإدخال وتأثيرها على الفروق في الإخراج — يعمل مع Chosen Plaintext وKnown Plaintext. ابتكره Eli Biham وAdi Shamir
Integral Cryptanalysisمفيد ضد Block Ciphers المبنية على Substitution-Permutation Networks — امتداد لـ Differential Cryptanalysis. ابتكره Lars Knudsen
Quantum Cryptanalysisاختراق الخوارزميات التشفيرية بـ Quantum Computer — Shor Algorithm لـ RSA وECDH وGrover Algorithm لـ AES وHash Functions

هجمات Cryptography

الهجومالشرحالمعرفة المطلوبة
Ciphertext-only Attackالمهاجم لديه فقط مجموعة من الـ Ciphertexts — يُحلِّلها لإيجاد أنماط تُلمِح للمفتاح. الأصعب والأقل فعاليةCiphertexts فقط
Known-plaintext Attackالمهاجم يعلم بعض كتل Plaintext مع Ciphertext المقابل والخوارزمية — يستنتج المفتاح. مثال لـ Linear CryptanalysisPlaintext + Ciphertext (محدود)
Chosen-plaintext Attackالمهاجم يختار Plaintexts ويحصل على Ciphertexts المقابلة — يستنتج المفتاحوصول لجهاز التشفير
Adaptive Chosen-plaintextكـ Chosen-plaintext لكن المهاجم يُعدِّل استعلاماته بناءً على نتائج سابقةوصول تفاعلي لجهاز التشفير
Chosen-ciphertext Attackالمهاجم يختار Ciphertexts ويحصل على Plaintexts المقابلة لاستخراج المفتاحوصول لقناة الاتصال
Related-Key Attackالمهاجم يحصل على Ciphertexts مشفَّرة بمفتاحَين مختلفَين ذوَي علاقة رياضية (مثل مفاتيح Wi-Fi المشتقّة من بعضها)Ciphertexts بمفتاحَين مترابطَين
Dictionary Attackالمهاجم يبني قاموسًا من Plaintexts وCiphertexts المقابلة مسبقًا — يُستخدَم لكسر المفاتيح وكلمات المرورقاموس مُسبَق البناء
Timing Attackقياس الوقت الدقيق لتنفيذ عمليات Modular Exponentiation — يستنتج Plaintext من أوقات التنفيذ المتفاوتةوقت التنفيذ
Man-in-the-Middle Attack (Crypto)اعتراض الاتصال + التفاوض على باراميترات التشفير + فكّ تشفير المحتوى. يُنفَّذ على أنظمة تبادل المفاتيح العامةاعتراض قناة الاتصال
Side-Channel Attackمراقبة العوامل البيئية الفيزيائية: استهلاك الطاقة والمجال الكهرومغناطيسي والإضاءة والتوقيت والصوتإشارات جانبية فيزيائية
Hash Collision Attackإيجاد رسالتَين مختلفتَين تنتجان نفس Hash Output — يُتيح تزوير التوقيع الرقمي. SHA-1 عرضة لهذا الهجوم—
Rainbow Table Attackجدول مُحسَّب مسبقًا لكل كلمات المرور المحتملة وقيم Hash المقابلة — يستخدم Time-memory Trade-off لعكس Hash Functionsجدول مُسبَق البناء
Brute-Force Attackتجربة كل التوليفات الممكنة للمفتاح حتى إيجاد الصحيح — مضمون الجدوى لكن يستغرق وقتًا طويلًا بحسب طول المفتاح—
Meet-in-the-Middle Attackيُشفِّر من طرف ويفكّ التشفير من الطرف الآخر ← يلتقيان في المنتصف — أفضل هجوم على الخوارزميات المتعدّدة المفاتيح (مثل 3DES). يستخدم Time-Space Trade-off ومبدأ Birthday Paradox—
Padding Oracle Attackاستغلال التحقّق من Padding في رسائل مُشفَّرة لفكّ الـ Ciphertext — خاصةً على خوارزميات CBC. يُسمّى Vaudenay Attackوصول لـ Padding Oracle
DUHK AttackDon't Use Hard-coded Keys — استغلال ANSI X9.31 RNG مع Seed Key مضمَّن في الكود لفكّ تشفير بيانات VPN—
DROWN AttackCross-protocol Weakness — يُهاجِم سيرفرات تدعم SSLv2 و TLS. فكّ تشفير TLS Connections باستخدام SSLv2 Probes بنفس المفتاح الخاص. جزء من MITM Online—

04هجمات Quantum Computing وهجمات Blockchain

مخاطر Quantum Computing على التشفير

  • Breaking Classical Cryptographic Systems: Shor Algorithm يكسر RSA وECDH — Grover Algorithm يُضعِف AES والـ Hash Functions
  • Data Harvesting for Future Decryption (Harvest-Now, Decrypt-Later): جمع بيانات مُشفَّرة الآن لفكّ تشفيرها مستقبلًا بـ Quantum Computer
  • Decrypting Secure Communications: SSL/TLS وVPNs تعتمد على Public-key Cryptography المعرّضة للهجوم الكمّي
  • Quantum-enhanced Eavesdropping: أجهزة استشعار كمّية تعترض الاتصالات المشفَّرة بدقة غير مسبوقة
  • Undermining Blockchain Security: استخراج Private Keys من Public Keys وكسر الـ Hash وDigital Signatures

2. Quantum Side-Channel Attackاستغلال تسرّب معلومات من التنفيذ الفيزيائي لأنظمة التشفير الكمّي — تحليل Quantum Noise والتوقيت واستهلاك الطاقة
3. Classical-to-Quantum Transition Attackاستغلال ثغرات فترة الانتقال من التشفير الكلاسيكي للكمّي — أنظمة Hybrid قد تُظهِر ضعفًا أو مشاكل Interoperability
4. Harvest-Now, Decrypt-Later Attackاعتراض وتخزين بيانات مُشفَّرة الآن لفكّ تشفيرها مستقبلًا حين تصبح Quantum Computers قادرة على كسر التشفير الحالي
5. Quantum Trojan Horse Attackتضمين أجهزة أو مكوّنات Quantum خبيثة في نظام التشفير الكمّي لجمع ونقل معلومات حسّاسة للمهاجم خفيةً
6. Quantum Supply Chain Attackاستهداف سلسلة توريد العتاد والبرمجيات الكمّية — تلاعب في المكوّنات أو Firmware لزرع Backdoors أو دوائر Quantum خبيثة
7. Quantum-Computer Sabotage Attackإجراءات فيزيائية أو إلكترونية لتعطيل أو تدمير أجهزة Quantum Computer — إتلاف العتاد لتعطيل التطبيقات والبحث الحرج
8. Fault-Injection Attack on Quantum Hardwareزرع أخطاء عمدية في نظام Quantum بالتلاعب في البيئة (درجة الحرارة والمجال الكهرومغناطيسي) — تغيير الحالات الكمّية للكشف عن معلومات حسّاسة

الدفاع ضد هجمات Cryptography

  • منح وصول مفاتيح التشفير للتطبيق أو المستخدم مباشرةً
  • نشر IDS لمراقبة تبادل ووصول المفاتيح
  • تشفير المفاتيح بـ Passphrases عند تخزينها على القرص
  • عدم وضع المفاتيح في الكود المصدري أو الثنائيات
  • عدم السماح بنقل المفاتيح الخاصة لتوقيع الشهادات
  • استخدام مفاتيح 256-bit للخوارزميات Symmetric في التعاملات الكبيرة
  • تطبيق Message Authentication للتشفير Symmetric-key
  • تصميم تطبيقات وبروتوكولات تتجنّب علاقات المفاتيح البسيطة (KDF)
  • الترقية لأحدث معايير الأمان
  • استخدام Key Schedules قوية لتخفيف Related Key Attacks
  • استخدام HSMs لتعزيز أمان المفاتيح التشفيرية
  • عدم استخدام مفتاح تشفير واحد لأغراض متعدّدة
  • استخدام أنظمة Cryptosystems متكرّرة (Redundant)
  • تطبيق Key Rotation دوري
  • استخدام التوقيعات الرقمية للرسائل والوثائق الهامة والتحقّق منها
  • استخدام Hardware-based RNGs لتوليد مفاتيح وNonces وIVs

الدفاع ضد هجمات Blockchain

  • تطبيق Decentralized Identifiers (DIDs) للتحقّق من الهوية
  • استخدام Zero-Knowledge Proofs للتحقّق من المعاملات بدون كشف معلومات حسّاسة
  • تخزين المفاتيح التشفيرية في HSMs
  • استخدام Multi-signature Wallets تتطلّب مفاتيح متعدّدة للتفويض
  • تطبيق أنظمة مراقبة Real-time أو Machine Learning لاكتشاف أنماط معاملات غير طبيعية (Double-spending)
  • دمج Proof-of-Work مع Proof-of-Stake لتخفيف مخاطر استهلاك الطاقة
  • تطبيق حماية DDoS متقدّمة لشبكات Blockchain

الدفاع ضد هجمات Quantum Computing

  • استخدام خوارزميات Quantum-resistant (Lattice-based، Hash-based، Code-based)
  • تطبيق Quantum Key Distribution (QKD)
  • دمج التشفير الكلاسيكي مع Quantum-resistant Algorithms خلال فترة الانتقال
  • استخدام مفاتيح أكبر للتشفير Symmetric لمواجهة الضعف الكمّي
  • Key Rotation دوري لتقليل فترة التعرّض
  • حماية ضد Side-channel Attacks (Power Analysis والـ EM Emissions)

الخلاصة العامة للموديول

الموديول الأخير ناقش أهداف Cryptography (CIA + Nonrepudiation)، وأنواع التشفير (Symmetric وAsymmetric)، وخوارزميات Symmetric الرئيسية (DES و3DES وAES وRC4 وRC5 وRC6 وBlowfish وTwofish وThreefish وSerpent وTEA وCAST-128 وGOST وCamellia)، وخوارزميات Asymmetric (DSA وRSA وDiffie-Hellman وECC وYAK)، ودوال Hash (MD5 وSHA وRIPEMD-160 وHMAC وGOST)، وأوضاع Block Cipher (ECB وCBC وCFB وCounter) وAuthenticated Encryption (EtM وE&M وMtE وAEAD)، وتطبيقات Cryptography (PKI وDigital Signatures وSSL/TLS وPGP وGPG وBlockchain)، و15+ هجوم Cryptanalysis، و8 هجمات Quantum Computing، و5 هجمات Blockchain، والإجراءات المضادة.

$ cat ./module20_summary.txt
  • Symmetric سريع لكن يُعاني مشكلة توزيع المفتاح — Asymmetric يحلّ المشكلة لكن أبطأ — PGP يجمع الاثنَين
  • 3DES = DES Encrypt (K1) → DES Decrypt (K2) → DES Encrypt (K3) — الخيار الأول (3 مفاتيح مختلفة) هو الأكثر أمانًا
  • AES هو المعيار الحالي — 128-bit Block مع مفتاح 128/192/256-bit وعدد دورات يتغيّر بحسب المفتاح
  • CBC أكثر أمانًا من ECB لأن كل كتلة تعتمد على الكتلة السابقة — لكن لا يسمح بالمعالجة المتوازية
  • EtM (Encrypt-then-MAC) هو الأكثر أمانًا بين أوضاع Authenticated Encryption
  • Harvest-Now, Decrypt-Later هو أخطر تهديد كمّي على المدى الطويل — يستهدف البيانات المُشفَّرة اليوم
  • 51% Attack الأكثر شيوعًا في Blockchain — السيطرة على نصف القدرة الحسابية = التحكّم في الشبكة

Cryptography ليست جدارًا حصينًا أبديًا — هي سباق دائم. DES حُلَّ في ساعات، SHA-1 تعرّض لـ Collision، RSA سيُكسَر بـ Quantum Computers. الأمان الحقيقي يكمن في فهم هذا السباق: ترقية الخوارزميات وتدوير المفاتيح والانتقال للخوارزميات المقاومة للكمّ قبل أن تصبح Quantum Computers سلاحًا فعليًا.

Exam Tip

أسئلة هذا الموديول تُركِّز على: مقارنة Symmetric وAsymmetric، خوارزميات AES وDES و3DES وRSA وECC ومفاتيحها، أوضاع Block Cipher (ECB وCBC وCFB وCounter)، الفرق بين EtM وE&M وMtE، كيفية عمل PGP (Compress → Random Key → Encrypt IDEA → Encrypt RSA)، الفرق بين هجمات Cryptanalysis (Ciphertext-only وChosen-plaintext وRainbow Table)، وهجمات Blockchain (51% وFinney وEclipse وRace وSandwich).
