01مفاهيم المسح الشبكي الأساسية

المسح هو امتداد موسَّع للاستطلاع — عملية جمع معلومات مفصَّلة إضافية عن الهدف باستخدام تقنيات استطلاع معقَّدة وعدوانية. المسح نفسه مش الاختراق الفعلي، لكنه بيساعد المهاجم يتعلّم أكتر عن هدفه (أنظمة تشغيل، خدمات، أخطاء إعداد) عشان يختار استراتيجية الهجوم.

أهداف المسح الشبكي

1اكتشاف المضيفين النشطين وعناوين IP والمنافذ المفتوحة
2اكتشاف نظام التشغيل وبنية النظام (Fingerprinting)
3اكتشاف الخدمات الشغّالة على المضيفين
4اكتشاف ثغرات في المضيفين النشطين

أنواع المسح

01
Port Scanning
سرد المنافذ المفتوحة والخدمات — فحص الاتصال بمنافذ TCP/UDP لتحديد هل الخدمات شغّالة أو في حالة استماع.
02
Network Scanning
سرد المضيفين النشطين وعناوين IP — إجراء لتحديد المضيفين النشطين في الشبكة لمهاجمتهم أو تقييم أمانها.
03
Vulnerability Scanning
كشف نقاط ضعف معروفة — ماسح الثغرات مكوَّن من محرّك فحص وكتالوج يحتوي قائمة ملفات وثغرات شائعة.

02أعلام TCP والمصافحة الثلاثية

رأس TCP يحتوي أعلام (Flags) بتتحكّم في نقل البيانات عبر اتصال TCP — ستة أعلام، كل واحد بحجم بت واحد. أربعة بتحكم إنشاء/صيانة/إنهاء الاتصال (SYN، ACK، FIN، RST)، واثنان بيديّا تعليمات للنظام (PSH، URG).

العلمالوظيفة
SYNيُعلن إرسال رقم تسلسل جديد — غالبًا بيمثّل إنشاء اتصال (Three-way Handshake)
ACKيؤكّد استلام النقل ويحدّد رقم التسلسل التالي المتوقَّع
PSHيشير إن المرسل رفع عملية Push للمستقبل — بيُستخدَم في بداية ونهاية نقل البيانات
URGيأمر النظام بمعالجة البيانات فورًا كأولوية قصوى
FINيُضبَط على 1 للإعلان إن مفيش نقل تاني هيُرسَل، وإنهاء الاتصال
RSTيُضبَط عند وجود خطأ في الاتصال الحالي — المهاجمون يستخدموه لمسح المضيفين وتحديد المنافذ المفتوحة

اتصال TCP/IP (المصافحة الثلاثية)

TCP بروتوكول Connection-Oriented — بيعطي أولوية لإنشاء الاتصال قبل نقل البيانات.

1
إرسال SYN

المصدر بيبعت حزمة SYN للوجهة لبدء اتصال TCP.

2
استقبال SYN/ACK

الوجهة بترد بحزمة SYN/ACK عند استلام SYN.

3
إرسال ACK النهائي

المصدر بيبعت ACK لتأكيد حزمة ACK/SYN — ده بيُطلق اتصال "مفتوح" يستمر حتى إرسال FIN أو RST.

عند الإنهاء: المرسل بيبعت FIN أو RST بعد انتهاء النقل، المستقبل بيرد بـ ACK ثم بيبعت FIN خاصته، وبعدين يُنهى الاتصال.

03أدوات المسح الأساسية

الأداةالوظيفة
Nmapماسح أمني لاستكشاف الشبكة — بيرسم "خريطة" للشبكة عبر حزم مصمَّمة خصيصًا وتحليل الاستجابات. يدعم مسح TCP/UDP، كشف نظام التشغيل، كشف الإصدار، Ping Sweeps
Hping3أداة سطر أوامر لمسح الشبكة وصياغة الحزم لبروتوكول TCP/IP — تدقيق أمان الشبكة، اختبار الجدار الناري، اكتشاف MTU، Traceroute متقدّم، بصمة نظام التشغيل عن بُعد
Metasploitمشروع مفتوح المصدر يوفّر بنية تحتية وأدوات لاختبار الاختراق والتدقيق الأمني — نهج معياري بيدمج أي Exploit مع أي Payload
NetScanTools Proأداة تحقيق لاستكشاف ومراقبة الأجهزة على الشبكة — عناوين IPv4/IPv6، أسماء مضيفين، نطاقات، بريد إلكتروني، روابط

أوامر Hping3 الأساسية

hping3 — essential commands
hping3 -1 10.0.0.25                      # ICMP ping
hping3 -A 10.0.0.25 -p 80                # ACK scan على المنفذ 80 (فحص جدار ناري)
hping3 -2 10.0.0.25 -p 80                # UDP scan
hping3 192.168.1.103 -Q -p 139           # جمع أرقام التسلسل الأولية (ISN)
hping3 -S 72.14.207.99 -p 80 --tcp-timestamp   # فحص الجدار الناري والـ Timestamp
hping3 -8 50-60 -S 10.0.0.25 -V          # SYN scan على نطاق منافذ 50-60
hping3 -1 10.0.1.x --rand-dest -I eth0   # فحص subnet كامل بحثًا عن مضيفين نشطين
hping3 -9 HTTP -I eth0                   # اعتراض كل ترافيك يحمل توقيع HTTP

04تقنيات اكتشاف المضيفين النشطين

اكتشاف المضيفين (Host Discovery) هو المهمة الأساسية الأولى في عملية المسح — بيوفّر حالة دقيقة للأنظمة في الشبكة، فبيتجنّب المهاجم مسح كل منفذ على كل نظام من غير داعي.

التقنيةالآليةميزة رئيسية
ARP Ping Scanحزم ARP لاكتشاف كل الأجهزة النشطة في نطاق IPv4 حتى لو مخفية خلف جدران نارية صارمةالأكثر كفاءة ودقة — بيُعالج طلبات وإعادة إرسال ARP تلقائيًا
UDP Ping ScanNmap بيبعت حزم UDP (المنفذ الافتراضي 40,125)كشف أنظمة خلف جدران نارية بفلترة TCP صارمة تنسى UDP
ICMP ECHO Ping Scanحزم ICMP للهدف — لا يشمل تجريد منفذ، مختلف عن Port Scanningتحديد المضيفين الشغّالين بسرعة
ICMP ECHO Ping Sweepطلبات ICMP ECHO متعدّدة لمضيفين كتير لتحديد نطاق IP حي — عبر Zenmap بخيار -PEجرد كامل للأنظمة الحية في Subnet
ICMP Timestamp/Address Mask Pingبديل لـ ICMP ECHO التقليدي — استعلام Address Mask لمعرفة Subnet Mask (-PM في Zenmap)فعّال لما الأدمن يحجب ICMP Echo التقليدي
TCP SYN Ping Scanبدء مصافحة ثلاثية بإرسال SYN فارغ — الهدف بيرد بـ ACKبدون اتصال فعلي، فمفيش سجلات — تخفٍّ عالي
TCP ACK Ping Scanإرسال حزمة ACK فارغة مباشرة — الهدف بيرد بـ RST لأنه مفيش اتصال سابقفعّال لتجاوز جدران نارية بتحجب SYN بس
IP Protocol Ping Scanحزم Ping بأي رقم بروتوكول IP محدَّد — بنفس صيغة TCP/UDP Pingيجرّب بروتوكولات IP مختلفة لإيجاد استجابة

05اكتشاف المضيفين بالذكاء الاصطناعي وPing Sweep

المهاجمون يقدروا يستخدموا ChatGPT أو تقنيات AI توليدية تانية لأتمتة اكتشاف المضيفين عبر Prompts مباشرة:

"Run a fast but comprehensive Nmap scan against scan1.txt with low verbosity and write the results to scan2.txt"

Angry IP Scanner — أداة Ping Sweep

ماسح عناوين IP ومنافذ — بيفحص أي نطاق IP وأي منفذ، بيعمل Ping لكل عنوان IP للتحقق من نشاطه، وممكن يحلّل اسم المضيف ويحدّد عنوان MAC ويفحص المنافذ. ميزات إضافية: معلومات NetBIOS (اسم الحاسوب، اسم مجموعة العمل، المستخدم المسجَّل دخوله)، نطاقات IP مفضَّلة، كشف سيرفر ويب. بيستخدم نهج Multithreaded — خيط مسح منفصل لكل عنوان IP لزيادة السرعة.

06تقنيات اكتشاف المنافذ الأساسية

01
TCP Connect/Full-Open Scan
الأكثر موثوقية بين أنواع مسح TCP — استدعاء connect() لنظام التشغيل بيحاول فتح اتصال لكل منفذ. اتصال ناجح = المنفذ في حالة استماع؛ خطأ = المنفذ غير قابل للوصول.
02
Stealth Scan (Half-Open / SYN Scan)
إعادة تعيين الاتصال فجأة قبل اكتمال المصافحة الثلاثية — إرسال SYN بس. لو المنفذ مفتوح، الهدف بيرد بـ SYN/ACK؛ لو مغلق، بيرد بـ RST. يتجاوز قواعد الجدار الناري وآليات التسجيل (-sS في Zenmap).
03
Inverse TCP Flag Scan
إرسال حزم بعلم TCP مضبوط (FIN، URG، PSH) أو بدون أعلام — منفذ مفتوح = بدون استجابة، منفذ مغلق = RST. وفقًا لـ RFC 793، حزمة RST/ACK بتُرسَل عند إغلاق منفذ.
04
Xmas Scan
نوع من Inverse TCP بأعلام FIN وURG وPUSH مضبوطة معًا — بدون استجابة = منفذ مفتوح، RST = منفذ مغلق. يعمل فقط على مضيفي UNIX (كود BSD Networking) — ضد Windows كل المنافذ تظهر مفتوحة خطأً.

07تقنيات اكتشاف المنافذ المتقدّمة

TCP Maimon Scan

مشابه جدًا لـ NULL وFIN وXmas scan، لكن الفحص المستخدَم هنا FIN/ACK — في أنظمة BSD كتيرة، المنفذ مفتوح لو الحزمة اتسقطت استجابة للفحص.

ACK Flag Probe Scan

إرسال حزم TCP بعلم ACK وتحليل معلومات رأس حزم RST المستلَمة (حقلي TTL وWINDOW) لتحديد حالة المنفذ — يستغل ثغرات في مكدَّس TCP/IP المشتق من BSD.

النوعالآلية
TTL-Basedإرسال آلاف حزم ACK لمنافذ TCP مختلفة وتحليل قيمة حقل TTL في حزم RST (nmap --ttl [time] [target])
Window-Basedتحليل قيمة حقل Window في حزم RST — مفيد لما كل المنافذ بترجّع نفس قيمة TTL (-sW في Zenmap)

يساعد كمان في فحص أنظمة الفلترة: مفيش استجابة = منفذ مُفلتَر (جدار ناري Stateful موجود)؛ استجابة RST = منفذ غير مُفلتَر (لا جدار ناري).

IDLE/IPID Header Scan

بيبعت عنوان مصدر مُزوَّر لحاسوب لتحديد الخدمات المتاحة — مسح أعمى بالكامل لمضيف بعيد. المنفذ "مفتوح" لو تطبيق بيستمع عليه — إرسال SYN بيرجّع SYN|ACK (مفتوح) أو RST (مغلق).

UDP Scan

مفيش مصافحة ثلاثية في مسح UDP — أصعب من TCP لأنك تقدر تبعت حزمة لكن مش تقدر تحدّد هل المضيف حي أو ميت أو مُفلتَر. لو بعتّ حزمة UDP لمنفذ بدون تطبيق مرتبط، مكدَّس IP بيرجّع ICMP_PORT_UNREACH — أي خطأ ICMP يعني المنفذ مغلق، أما المنافذ اللي ماردّتش يبقى إما مفتوحة أو مُفلتَرة (-sU في Zenmap).

08تقنيات مسح إضافية واكتشاف إصدار الخدمة

SCTP وSSDP وList وIPv6 Scans

النوعالوصف
SCTP INIT Scanبروتوكول طبقة نقل موثوق قائم على الرسائل، بديل لـ TCP/UDP — يُستخدَم لـ VoIP وIP Telephony وSS7/SIGTRAN. ارتباط SCTP بيتكوّن من مصافحة رباعية
SCTP COOKIE ECHO Scanنوع متقدّم — إرسال COOKIE ECHO chunk؛ منفذ مفتوح = إسقاط صامت، منفذ مغلق = رد ABORT. غير محجوب بقواعد جدار ناري غير Stateful (-sZ في Zenmap)، فقط IDS متقدّم يكتشفه
SSDP Scanبروتوكول اكتشاف خدمة بسيط للتواصل عبر عناوين Multicast — يتحكّم في UPnP. يُستخدَم لكشف ثغرات UPnP المؤدية لـ Buffer Overflow أو DoS
List Scanيولّد ويطبع قائمة IPs/أسماء بدون Ping أو مسح فعلي — كل العناوين تظهر "not scanned"
IPv6 Scanمساحة البحث الأكبر (64 بت) بتخليه أصعب وأعقد من مسح IPv4 — بعض الأدوات مش بتدعم Ping Sweeps على IPv6، فلازم حصاد عناوين من ترافيك الشبكة أو السجلات

مسح المنافذ بالذكاء الاصطناعي واكتشاف إصدار الخدمة

ai prompts for port + service discovery
"Use Nmap to find open ports on target IP 10.10.1.11"
"Perform stealth scan on target IP 10.10.1.11 and display the results"
"Use Nmap to scan open ports, MAC details, services running on open ports with their versions on target IP 10.10.1.11"

اكتشاف إصدار الخدمة بيساعد المهاجم يحدّد أي استغلالات النظام الهدف عرضة ليها — بعض إصدارات البروتوكولات غير آمنة وتسمح بالاختراق عبر استغلال الثغرة.

تقنيات تقليل زمن مسح Nmap

  • تجنّب الفحص الكثيف لو محتاج معلومات محدودة فقط، وتحديد عدد المنافذ المفحوصة
  • تخطّي -sn لو الهدف بس التحقق من الاتصال، وتجنّب الأنواع المتقدّمة (-sC، -sV، -O، --traceroute، -A) لو مش ضرورية
  • تحسين معامل التوقيت -T حسب شراسة المسح المطلوبة
  • فصل مسح UDP عن TCP وتحسينه بشكل منفصل — متأثر أكتر بـ ICMP Rate-Limiting
  • استخدام أحدث إصدار من Nmap، تنفيذ نسخ متوازية، المسح من موقع شبكي مناسب، وزيادة النطاق الترددي المتاح

09اكتشاف نظام التشغيل (Banner Grabbing)

Banner Grabbing أو "OS Fingerprinting" طريقة لتحديد نظام التشغيل الشغّال على نظام هدف بعيد — أهمّية حرجة لأن معظم الثغرات خاصة بنظام تشغيل محدَّد، وده بيساعد المهاجم يصيغ استراتيجية هجوم مناسبة.

فعّال
Active Banner Grabbing
يعتمد على إن مكدَّس IP لكل نظام تشغيل له طريقة فريدة للرد على حزم TCP مصمَّمة خصيصًا — المهاجم بيبعت حزم مُشوَّهة متنوّعة ويقارن الاستجابات بقاعدة بيانات.
سلبي
Passive Banner Grabbing
بدل الاعتماد على مسح الهدف، البصمة السلبية بتلتقط حزم من الهدف عبر Sniffing. يشمل: استخراج معلومات من رسائل الخطأ، تحليل ترافيك الشبكة، وفحص امتدادات الصفحة (مثلًا .aspx → سيرفر IIS ومنصّة Windows).

10المسح خارج IDS والجدران النارية — الجزء الأول

IDS والجدران النارية آليات أمنية لمنع وصول المهاجم — لكن حتى هذه الأنظمة عندها قيود. المهاجمون بيستغلّوا القيود دي بتقنيات متعدّدة.

التقنيةالآلية
Packet Fragmentationتقسيم حزمة الفحص لعدة حزم أصغر — معظم IDS بتُعدَّ لتخطّي الحزم المجزَّأة أثناء مسح المنافذ لأن معالجتها بتستهلك موارد كتير
SYN/FIN Scanning باستخدام IP Fragmentsتعديل لتقنيات سابقة — رأس TCP بيتقسّم لعدة حزم لتجاوز جهاز فلترة الحزم
Source Routingحقل IP Options بيخزّن معلومات توجيه المصدر — قائمة عناوين IP اللي الحزمة بتمر بيها لوجهتها
Source Port Manipulationالتلاعب برقم المنفذ المصدر الفعلي بأرقام منافذ شائعة — استغلال ثقة الأدمن العمياء في أرقام منافذ معروفة (HTTP، DNS، FTP)
IP Address Decoyتوليد أو تحديد عناوين IP وهمية لخداع IDS/Firewall — يصعب تحديد مين فعليًا بيمسح الشبكة ومين عناوين وهمية
IP Address Spoofingتزوير عنوان IP المصدر لتجاوز جدران نارية بتفلتر بناءً على المصدر
MAC Address Spoofingاستخدام عناوين MAC مزيَّفة لانتحال مستخدمين شرعيين وتجاوز قواعد فلترة MAC

11المسح خارج IDS والجدران النارية — خوادم البروكسي

حزم مخصَّصة وتقنيات إضافية

  • Creating Custom Packets: أدوات صياغة حزم زي Colasoft Packet Builder وNetScanTools Pro لصنع وإرسال تدفّقات حزم مخصَّصة ببروتوكولات ومعدّلات نقل مختلفة
  • Randomizing Host Order: مسح المضيفين بترتيب عشوائي (--randomize-hosts في Nmap) لتجنّب أنماط قابلة للكشف
  • Sending Bad Checksums: إرسال حزم بـ Checksums خاطئة لاختبار استجابة النظام المستهدَف

خوادم البروكسي (Proxy Servers)

تطبيق وسيط للاتصال بحواسيب أخرى — يُستخدَم كجدار ناري وحماية الشبكة المحلية، مضاعِف عناوين IP (NAT/PAT)، إخفاء هوية التصفّح جزئيًا، وتوفير النطاق الترددي.

ليه المهاجمون يستخدموا البروكسي

إخفاء هوية المهاجم هو التحدّي الأساسي — بيستخدم بروكسي لإخفاء عنوان IP الحقيقي، فسجلات السيرفر الهدف بتسجّل عنوان البروكسي مش عنوان المهاجم الفعلي.

تسلسل البروكسي (Proxy Chaining)

بيزيد تخفّي المهاجم على الإنترنت — كل ما زاد عدد سيرفرات البروكسي المستخدَمة، زادت درجة التخفّي. المستخدم بيطلب مورد، عميل البروكسي بيتصل بسيرفر بروكسي ويمرّر الطلب، السيرفر بيشيل معلومات هوية المستخدم ويمرّر الطلب لسيرفر بروكسي تاني.

المخترق الأخلاقي، بعكس المخترق العادي، لازم يتبنّى إجراءات مواجهة للثغرات اللي اكتشفها — معرفة الثغرات بدون حماية ضدها عديمة الفائدة.

مواجهة Port Scanning وBanner Grabbing

تعطيل أو تغيير الـ Banner — منفذ مفتوح يعني خدمة/Banner شغّال عليه. لما المهاجم يتصل بمنفذ مفتوح عبر تقنيات Banner Grabbing، النظام بيعرض Banner يحتوي معلومات حساسة (نظام التشغيل، نوع السيرفر، الإصدار) — إخفاء أو تعديل البيانات دي بيمنع استغلالها.

--منهجية المسح الشبكي الكاملة

من اكتشاف المضيفين وحتى صياغة استراتيجية الهجوم — الترتيب المنطقي الكامل لمسح الشبكة
  • ابدأ دايمًا باكتشاف المضيفين النشطين قبل أي مسح منافذ — يوفّر وقت كبير ويقلّل الترافيك غير الضروري
  • اختر تقنية المسح حسب درجة التخفّي المطلوبة — TCP Connect للموثوقية، SYN/Stealth للتخفّي، Xmas/FIN لتجاوز فلاتر بسيطة
  • بعد تحديد المنافذ المفتوحة، نفّذ اكتشاف إصدار الخدمة ونظام التشغيل فورًا — ده بيحدّد الثغرات المحتملة بدقة
  • لو الهدف محمي بـ IDS/Firewall، ادمج تقنيات تجزئة الحزم والتزوير والبروكسي بدل الاعتماد على تقنية واحدة
  • وثّق كل خطوة والنتائج — ده الأساس لبناء استراتيجية الاستغلال في المراحل اللاحقة

الخلاصة العامة للموديول

الموديول ده غطّى مسح الشبكات بعمق — من اكتشاف المضيفين النشطين بتقنيات Ping متعدّدة، مرورًا بعشرات تقنيات مسح المنافذ (من TCP Connect وحتى SCTP COOKIE ECHO)، واكتشاف نظام التشغيل عبر Banner Grabbing، ووصولًا لتقنيات تجاوز IDS/Firewall وإجراءات المواجهة.

$ cat ./cehv13_module03_summary.txt
  • المسح امتداد موسَّع للاستطلاع — مش الاختراق نفسه، لكنه بيبني صورة دقيقة لاستراتيجية الهجوم
  • اكتشاف المضيفين النشطين خطوة أولى إلزامية — بيوفّر وقت ويقلّل الأثر المكتشَف قبل مسح المنافذ
  • تقنيات مسح المنافذ متعدّدة بتنوّع في التخفّي والموثوقية — من TCP Connect الموثوق جدًا وحتى IDLE Scan الأعمى بالكامل
  • Banner Grabbing (نشط أو سلبي) حرج لأن معظم الثغرات مرتبطة بنظام تشغيل أو إصدار خدمة محدَّد
  • تقنيات تجاوز IDS/Firewall (تجزئة، تزوير، بروكسي) ضرورية ضد بيئات محمية بشكل جيد
  • الذكاء الاصطناعي بقى أداة فعّالة لأتمتة كل مراحل المسح — من اكتشاف المضيفين وحتى تحديد الإصدارات
  • إجراءات المواجهة (إخفاء Banner، كشف IP Spoofing، أدوات اكتشاف المسح) جزء أساسي من أي دفاع احترافي

الفكرة الجوهرية للموديول: كل تقنية مسح هي محاولة للإجابة على سؤال واحد بطريقة مختلفة — "هل في حد موجود هنا، وإيه اللي بيشتغل؟" التنوّع الهائل في التقنيات مش تعقيد بلا داعي، هو استجابة مباشرة لتنوّع الدفاعات اللي بتحاول تمنع الإجابة على السؤال ده.

Professional Mindset

احفظ خيارات Zenmap/Nmap المختصرة بدقة (-sS، -sU، -O، إلخ) لأن الامتحان بيختبرها مباشرة. افهم الفرق الدقيق بين كل نوع Ping/Scan من حيث الاستجابة المتوقَّعة (SYN/ACK مقابل RST مقابل لا استجابة) — ده أساس فهم ليه تقنية معيّنة بتنجح ضد دفاع معيّن وتفشل ضد تاني.
