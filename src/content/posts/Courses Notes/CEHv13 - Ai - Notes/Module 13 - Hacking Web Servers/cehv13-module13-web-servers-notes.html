01مفاهيم الـ Web Server — المكوّنات وأسباب الاختراق

عمليات الـ Web Server

الـ Web Server هو نظام حاسوبي يُخزِّن ويُعالج ويُسلِّم صفحات الويب للعملاء حول العالم عبر بروتوكول HTTP. العميل يبدأ عملية الاتصال بطلبات HTTP: لما يحتاج مصدرًا زي صفحة ويب أو صورة أو فيديو، متصفحه يولِّد طلب HTTP يُرسَل للسيرفر. السيرفر بناءً على الطلب يجمع المحتوى المطلوب من مساحة التخزين أو من Application Servers ويرد على العميل باستجابة HTTP مناسبة.

مكوّنات الـ Web Server

المكوّنالوصف
Document Rootأحد المجلدات الجذرية اللي بتخزّن ملفات HTML الحرجة الخاصة بصفحات الدومين، واللي هتُرسَل ردًا على الطلبات. مثال: لو الطلب www.certifiedhacker.com والـ Document Root اسمه certroot ومخزّن في /admin/web، فعنوان المجلد هو /admin/web/certroot. ولو الطلب الكامل www.certifiedhacker.com/P-folio/index.html هيدوّر السيرفر على /admin/web/certroot/P-folio/index.html
Server Rootالمجلد الأعلى في شجرة الدليل، وفيه ملفات إعدادات السيرفر وملفات الـ Log والملفات التنفيذية. وبيحتوي عادةً على: conf (ملفات الإعدادات)، logs (ملفات Access وError Logs)، cgi-bin (سكربتات CGI أو ملفات تنفيذية من جهة السيرفر)
Virtual Document Treeيوفّر تخزينًا على جهاز أو قرص مختلف بعد امتلاء القرص الأصلي. حسّاس لحالة الأحرف (Case-Sensitive) ويُستخدم لتوفير حماية على مستوى الـ Object. في نفس مثال Document Root، لو المجلد admin/web/certroot مخزّن على قرص تاني، هيدوّر السيرفر على نفس المسار في القرص الجديد
Virtual Hostingتقنية استضافة عدة دومينات أو مواقع على نفس السيرفر، بتسمح بمشاركة الموارد بين سيرفرات متعدّدة، وبتُستخدم في الشركات الكبيرة. أنواعها: Name-based، IP-based، Port-based
Web Proxyسيرفر بروكسي يقف بين العميل والسيرفر؛ كل الطلبات بتمرّ من خلاله. يُستخدم لمنع حظر IP والحفاظ على عدم الكشف عن الهوية (Anonymity)

مشاكل أمان الـ Web Server

هجمات مستوى الشبكة ونظام التشغيل ممكن تُصدّ بإجراءات أمان مناسبة زي الـ Firewalls وIDS. لكن الـ Web Servers ممكن يوصلها أي حد عبر الإنترنت من أي مكان، وده بيخلّيها معرَّضة جدًا للهجمات.

ليه الـ Web Servers بتتعرّض للاختراق؟

  • صلاحيات ملفات ومجلدات غير صحيحة
  • ملفات Default أو Backup أو Sample غير ضرورية
  • أخطاء إعدادات (Misconfigurations) في السيرفر ونظام التشغيل والشبكة
  • ثغرات (Bugs) في برمجيات السيرفر ونظام التشغيل وتطبيقات الويب
  • وظائف إدارية أو تصحيح أخطاء (Debugging) مفعَّلة أو متاحة على السيرفر
  • استخدام شهادات Self-Signed أو شهادات SSL بإعدادات خاطئة أو شهادات افتراضية وإعدادات تشفير ضعيفة
  • عدم استخدام سيرفر مخصَّص لخدمات الويب

أثر هجمات الـ Web Server

  • اختراق حسابات المستخدمين
  • تشويه الموقع (Website Defacement)
  • هجمات ثانوية تنطلق من الموقع
  • وصول Root لتطبيقات أو سيرفرات أخرى
  • التلاعب بالبيانات وسرقتها
  • ضرر بسمعة الشركة

02ثغرات السيرفرات الشهيرة — Apache وIIS وNginx

بنية Apache Web Server

Apache سيرفر HTTP مفتوح المصدر يُستخدم لتوصيل محتوى الويب عبر الإنترنت. يقدر يستضيف مواقع ويتعامل مع طلبات HTTP ويقدّم محتوى ثابت وديناميكي. يتميّز بأداء عالٍ وميزات أمان وتخصيص واسع عبر الـ Modules ومجتمع دعم كبير.

أبرز ثغرات Apache

الثغرةالشرح
HTTP Response Splittingتحدث لما إدخال غير مُتحقَّق منه يسمح للمهاجم بحقن Headers خبيثة في استجابات HTTP. ممكن تؤدّي لـ XSS أو Cache Poisoning أو كشف معلومات حسّاسة
HTTP/2 DoS — Endless Continuation Framesالمهاجم يرسل Headers متتالية عبر HTTP/2 تستهلك الذاكرة وتؤدّي لـ DoS، فالسيرفر يصبح غير مستجيب أو يتوقف
mod_macro Buffer Over-Readسوء تعامل الموديول مع توسيع الـ Macro يخلّيه يقرأ بعد نهاية الـ Buffer. يُستغَل بطلبات مصمَّمة خصيصًا تكشف معلومات من مناطق ذاكرة مجاورة

Improper Certificate Validation (Apache Airflow — FTP_TLS)تحقّق شهادات غير صحيح في اتصالات FTP_TLS يسمح باعتراض أو التلاعب بحركة FTP (MITM)

SQL Injection (Apache Submarine Server Core)تحييد غير صحيح لعناصر SQL يسمح بتنفيذ استعلامات عشوائية — وصول غير مصرّح، استخراج بيانات، أو تعديل قاعدة البيانات

بنية IIS Web Server

IIS (Internet Information Services) تطبيق Web Server من Microsoft بيشتغل على سيرفر ويرد على طلبات المتصفح. نسخة Windows Server منه مرنة وسهلة الإدارة لاستضافة الويب.

Trust Boundary Violation (Telerik Report Server)فصل غير كافٍ لحدود الصلاحيات يسمح لكيان غير موثَّق بالوصول لوظائف مقيَّدة — وقد يؤدّي للتلاعب بعمليات السيرفر

بنية Nginx Web Server

Nginx سيرفر عالي الأداء وقابل للتوسّع، يعمل كـ Reverse Proxy وLoad Balancer على بنية Master-Worker: عملية Master تشرف على عدة عمليات Worker مسؤولة عن معالجة طلبات العملاء، وكل Worker بيستخدم I/O غير حاجز (Non-Blocking) لإدارة اتصالات متعددة في Loop واحد. يدعم كمان Load Balancing متقدّم وCaching قوي وإنهاء SSL/TLS وLogging تفصيلي.

03أنواع هجمات الـ Web Server

DNS Server Hijacking

المهاجم يخترق سيرفر DNS ويغيّر إعداداته بحيث كل الطلبات المتوجّهة للـ Web Server الهدف تُعاد توجيهها لسيرفره الخبيث.

DNS Amplification Attack

الـ Recursive DNS Query طريقة لطلب تحويل DNS: الاستعلام يمرّ عبر سيرفرات DNS بشكل تكراري (Recursive) لحد ما يفشل في إيجاد تحويل اسم الدومين لعنوان IP.

Directory Traversal Attacks

المهاجم يستخدم تسلسل ../ (Dot-Dot-Slash) للوصول لمجلدات مقيَّدة خارج Root الخاص بالسيرفر، باستخدام أسلوب المحاولة والخطأ للوصول لمعلومات حسّاسة في النظام.

Website Defacement

تغييرات غير مصرَّح بها على محتوى صفحة واحدة أو الموقع كله، تؤدّي لتغيير المظهر البصري. المهاجمون بيحقنون كودًا لإضافة صور أو Popups أو نصوص، وفي بعض الحالات بيستبدلوا الموقع كله بدل صفحة واحدة.

Web Server Misconfiguration

نقاط ضعف في إعدادات بنية الويب تُستغَل لتنفيذ هجمات زي Directory Traversal واختراق السيرفر وسرقة البيانات. من أمثلتها: رسائل Debug/Error مُفصَّلة، مستخدمون Anonymous أو Default بكلمات مرور افتراضية، خدمات غير ضرورية مفعَّلة.

HTTP Response-Splitting Attack

المهاجم يضيف بيانات استجابة Header في حقل الإدخال بحيث يقسّم السيرفر الاستجابة لاستجابتين، مستغلًا سيرفر Apache ضعيف التحقّق من الإدخال بحقن Request Header مصمَّم خصيصًا يستخرج ردّين. المهاجم يتحكّم في الردّ الأول لتحويل المستخدم لموقع خبيث، أما الردود الأخرى فيتجاهلها المتصفح.

Web Cache Poisoning Attack

يستهدف موثوقية مصدر الـ Web Cache الوسيط: المهاجم يستبدل المحتوى المخزَّن لرابط معيّن بمحتوى مصاب. مستخدمو الـ Cache بيستخدموا المحتوى المسمَّم بدون علمهم بدل المحتوى الحقيقي والآمن.

SSH Brute Force Attack

بروتوكولات SSH تُنشئ نفقًا مشفَّرًا بين مضيفَين لنقل بيانات غير مشفَّرة عبر شبكة غير آمنة. المهاجم يقدر يعمل Brute Force لبيانات دخول SSH للوصول غير المصرّح للنفق، واللي بيُستخدم بعدين لنقل Malware واستغلالات تانية للضحايا من غير ما يتكشف.

FTP Brute Force with AI

المهاجم ممكن يستغل أدوات AI التوليدية زي ChatGPT لتنفيذ هذه المهمة باستخدام Prompt مناسب.

HTTP/2 Continuation Flood Attack

استغلال آلية تعامل HTTP/2 مع إطارات CONTINUATION: المهاجم يرسل عددًا كبيرًا منها عبر اتصال TCP واحد، ما يُثقل موارد سيرفر Apache ويسبّب حالة Denial-of-Service.

FrontJacking Attack

المهاجم يحقن أو يتلاعب بمكوّنات الواجهة الأمامية لتطبيق ويب عشان يخطف واجهة المستخدم أو تفاعلاته. يستهدف سيرفرات Nginx Reverse Proxy سيئة الإعداد في بيئات الاستضافة المشتركة، جامعًا بين CRLF Injection وHTTP Request Header Injection وXSS. المهاجم يحقن Host Header جديد لخطف تدفّق تنفيذ الـ Reverse Proxy واستبدال السيرفر الخلفي بسيرفر يتحكّم فيه هو.

04منهجية هجوم الـ Web Server

منهجية الهجوم على الـ Web Server بتتكوّن من 6 خطوات أساسية:

1
Information Gathering

كل مهاجم بيحاول يجمع أكبر قدر من المعلومات عن السيرفر الهدف، ثم يحلّلها للبحث عن ثغرات في آليات الأمان الحالية.

2
Web Server Footprinting

جمع معلومات عن الجوانب الأمنية للسيرفر بأدوات أو تقنيات Footprinting، لتحديد قدرات الوصول عن بُعد والبورتات والخدمات وجوانب أمان أخرى.

3
Website Mirroring

نسخ الموقع ومحتواه على سيرفر آخر للتصفح دون اتصال (Offline)، بحيث يقدر المهاجم يشوف البنية التفصيلية للموقع.

4
Vulnerability Scanning

إيجاد الثغرات والإعدادات الخاطئة بمساعدة أدوات آلية تُسمّى Vulnerability Scanners.

5
Session Hijacking

بعد تحديد جلسة العميل الحالية، المهاجم يستولي عليها بالكامل بتقنيات خطف الجلسات.

6
Web Server Passwords Hacking

استخدام أساليب كسر كلمات المرور زي Brute-Force وHybrid وDictionary Attacks لكسر كلمة مرور السيرفر.

جمع المعلومات من ملف Robots.txt

ملف robots.txt يحتوي قائمة مجلدات وملفات السيرفر اللي صاحب الموقع عايز يخفيها عن Web Crawlers. المهاجم يقدر ببساطة يطلب الملف من الـ URL ويستخرج معلومات حسّاسة زي بنية المجلد الجذري ومعلومات نظام إدارة المحتوى، وممكن كمان يحمّله بأداة Wget.

Footprinting / Banner Grabbing

الأداةالوصف
netcatجمع بيانات على مستوى النظام زي تفاصيل الحسابات، نظام التشغيل، إصدارات البرمجيات، أسماء السيرفرات، وتفاصيل مخطّط قاعدة البيانات (netcat.sourceforge.net)
httpreconأداة لبصمة Web Server متقدّمة — تنفّذ Banner Grabbing وتعداد أكواد الحالة وتحليل ترتيب الـ Headers، وتوفّر معلومات بصمة دقيقة (computec.ch)
Shodanيُستخدم لجمع معلومات عن سيرفرات IIS وتحسين القدرة على تنفيذ هجمات مستهدَفة وفعّالة

استغلال Apache mod_userdir لتعداد حسابات المستخدمين

المهاجمون يستغلّون موديول mod_userdir في Apache لتعداد حسابات المستخدمين بروابط زي /~username/. باستخدام Nmap، يقدر المهاجم يحدّد أسماء مستخدمين صالحة تساعد في الـ Brute Forcing أو هجمات التصيّد المستهدَفة.

nmap — enumerate apache userdir
# فحص أولي لتعداد المستخدمين الصالحين بقائمة كلمات افتراضية
nmap -p80 --script http-userdir-enum <target>

# فحص مخصَّص — ياخد ملف .txt كمصدر لأسماء المستخدمين ويختبره ضد الهدف
nmap -p80 --script http-userdir-enum --script-args userdir.users=<Wordlist.txt> <target>

# تجاوز الكشف بتغيير الـ User Agent
nmap -p80 --script http-brute --script-args http.useragent="<User_Agent>" <target>

Directory Brute Forcing

لما السيرفر يستقبل طلبًا لمجلد، بيرد بإحدى الطرق التالية:

  • إرجاع المصدر الافتراضي داخل المجلد
  • إرجاع خطأ (Error)
  • إرجاع قائمة بمحتوى المجلد (Directory Listing)

قوائم المجلدات أحيانًا بتحمل ثغرات زي صلاحيات وصول غير صحيحة ووصول غير مقصود لـ Web Root السيرفر. المهاجمون يستخدمون أدوات زي Dirhunt للبحث وتحليل المجلدات، وبعد اكتشاف مجلد يطلبوه ويحاولوا يوصلوا لقوائمه، أو يستغلّوا برمجيات سيرفر ضعيفة بتسمح بالوصول لقوائم المجلدات.

Directory Brute Forcing بالـ AI

المهاجمون يقدروا يستخدموا تقنيات AI لتحسين وأتمتة الهجوم، وينفّذوا هجمات Directory Traversal على الدومين الهدف بسهولة أكبر.

Vulnerability Scanning

  • تنفيذ فحص ثغرات لتحديد نقاط الضعف في الشبكة ومعرفة إمكانية استغلال النظام
  • استخدام أدوات زي Acunetix Web Vulnerability Scanner وFortify WebInspect لإيجاد الأجهزة والخدمات والثغرات
  • عمل Sniffing لحركة الشبكة لإيجاد أي أنظمة وخدمات وتطبيقات وثغرات نشطة
  • اختبار بنية السيرفر بحثًا عن إعدادات خاطئة ومحتوى قديم وثغرات بأدوات مثل Acunetix

فحص ثغرات Nginx باستخدام Nginxpwner

Nginxpwner أداة بلغة Python مصمَّمة لاكتشاف الإعدادات الخاطئة والثغرات الشائعة في سيرفرات Nginx القابلة للاستغلال.

bash — nginxpwner scan
# إنشاء ملف مؤقّت لتخزين قائمة مسارات URL محتملة
nano /tmp/pathlist

# تشغيل سكربت nginxpwner
python3 nginxpwner.py <target_URL> /tmp/pathlist

بعد التشغيل، المهاجم يحلّل المخرجات لتحديد الثغرات والإعدادات الخاطئة المحتملة في سيرفر Nginx الهدف.

إيجاد ثغرات قابلة للاستغلال

1
الدخول على Exploit Database

التوجّه لموقع exploit-db.com.

2
البحث بالكلمات المفتاحية

استخدام شريط البحث بكلمات تخص السيرفر الهدف مثل "Apache" أو "IIS" أو "nginx".

3
تطبيق الفلاتر

تضييق نتائج البحث بالفلاتر المتاحة.

4
مراجعة النتائج

تحديد الثغرات ذات الصلة من النتائج.

5
فتح تفاصيل الاستغلال

الاطّلاع على كود الاستغلال والوصف والمراجع.

6
التحقّق من التوافق

مطابقة الثغرات المكتشفة مع إصدارات وإعدادات السيرفر الهدف للتأكد من الانطباق.

7
تحميل واختبار الكود

تحميل كود الاستغلال إن كان مناسبًا واختباره على السيرفر الهدف.

كسر كلمة مرور الـ Web Server

استخدام تقنيات كسر كلمات المرور زي Brute Force وDictionary Attack وPassword Guessing، بأدوات مثل Hashcat وTHC Hydra وNcrack.

استخدام Application Server كـ Proxy

بعض السيرفرات مُعدَّة لتنفيذ وظائف Forwarding أو Reverse HTTP Proxy. المهاجمون يستغلّون هذه الوظائف لتنفيذ:

  • مهاجمة أنظمة طرف ثالث على الإنترنت
  • الاتصال بمضيفين عشوائيين داخل شبكة المؤسسة الداخلية
  • الاتصال مرة أخرى بخدمات تانية شغّالة على جهاز البروكسي نفسه

المهاجمون يستخدمون طلبات GET وCONNECT لاستخدام السيرفرات الضعيفة كـ Proxy للاتصال بالأنظمة الهدف والحصول على معلومات منها.

Path Traversal عبر NGINX Alias سيئ الإعداد

المهاجم يستغل إعدادًا خاطئًا في ملف nginx.conf يخص استخدام التوجيه alias:

nginx.conf — webroot misconfiguration
location /i {
    alias /data/w3/images/;
}

غياب الـ Trailing Slash بيسمح للمهاجم بالتلاعب في الـ URL للوصول لمجلدات وملفات خارج الـ Webroot المحدَّد.

05الإجراءات المضادة وأدوات الحماية

الإجراءات المضادة: التحديثات والـ Patches

  1. فحص الثغرات الحالية وتطبيق Patches وتحديث برمجيات السيرفر بانتظام
  2. قبل تطبيق أي Service Pack أو Hotfix أو Patch أمني، قراءة ومراجعة كل التوثيق ذي الصلة
  3. التأكد إن مستويات Service Packs وHotfixes وPatches متسقة على كل الـ Domain Controllers (DCs)
  4. التأكد من جدولة فترات توقّف السيرفر، وتوفّر نسخ احتياطية وأقراص إصلاح طوارئ كاملة
  5. تطبيق كل التحديثات، بصرف النظر عن نوعها، على أساس "عند الحاجة"
  6. اختبار Service Packs وHotfixes في بيئة تمثيلية غير إنتاجية قبل النشر الفعلي
  7. الاحتفاظ بخطة تراجع (Back-Out Plan) تسمح للنظام والمؤسسة بالرجوع لحالتها الأصلية بعد أي تطبيق فاشل
  8. جدولة ترقيات Service Pack دوريًا كجزء من صيانة العمليات، وعدم التأخر بأكثر من Service Packين

الإجراءات المضادة: البروتوكولات

  • حظر كل البورتات غير الضرورية وحركة ICMP والبروتوكولات غير اللازمة
  • تقوية Stack الخاص بـ TCP/IP وتطبيق أحدث Patches والتحديثات بانتظام
  • لو بروتوكولات غير آمنة زي Telnet وSMTP وFTP مستخدمة، اتخاذ إجراءات لتأمين الـ Authentication والاتصال، مثل استخدام سياسات IPsec
  • لو الوصول عن بُعد مطلوب، التأكد من تأمين الاتصالات باستخدام بروتوكولات Tunneling والتشفير
  • استخدام بروتوكولات آمنة زي TLS/SSL للتواصل مع السيرفر

الإجراءات المضادة: الحسابات

  • إزالة كل الموديولات والإضافات غير المستخدَمة
  • تعطيل حسابات المستخدمين الافتراضية غير المستخدَمة اللي اتعملت أثناء تثبيت نظام التشغيل
  • عند إنشاء Web Root Directory جديد، منح صلاحيات NTFS المناسبة (الأقل الممكن) للمستخدمين المجهولين على سيرفر IIS للوصول للمحتوى
  • التخلّص من مستخدمي قاعدة البيانات والإجراءات المخزَّنة غير الضرورية واتّباع مبدأ أقل الصلاحيات للتطبيق للدفاع ضد SQL Query Poisoning
  • استخدام صلاحيات ويب آمنة، وصلاحيات NTFS، وآليات تحكّم وصول .NET Framework بما فيها URL Authorization
  • إبطاء هجمات Brute-Force وDictionary بسياسات كلمات مرور قوية، وتطبيق تدقيق وتنبيهات لمحاولات الدخول الفاشلة

الإجراءات المضادة: الملفات والمجلدات

  • التخلّص من الملفات غير الضرورية داخل ملفات .jar
  • التخلّص من معلومات الإعدادات الحسّاسة داخل الـ Byte Code
  • تجنّب ربط مجلدات افتراضية (Virtual Directories) بين سيرفرين مختلفين أو عبر الشبكة
  • مراقبة وفحص كل سجلات خدمات الشبكة وسجلات الوصول للموقع وسجلات سيرفرات قواعد البيانات (مثل MS SQL Server وMySQL وOracle) وسجلات نظام التشغيل بانتظام
  • تعطيل عرض قوائم المجلدات (Directory Listings)
  • تعطيل تقديم أنواع ملفات معيّنة بإنشاء Resource Map
  • التخلّص من الملفات غير المتعلّقة بالويب مثل ملفات الأرشيف والنسخ الاحتياطية والملفات النصية وملفات Header/Include

كشف محاولات اختراق الـ Web Server

نظام كشف تغييرات الموقع (Website Change Detection System) بيعتمد على:

1
تشغيل سكربت على السيرفر

يكتشف أي تغييرات في ملف تنفيذي موجود أو ملف جديد على السيرفر.

2
مقارنة قيم Hash دوريًا

مقارنة Hash Values لملفات السيرفر بالقيمة الأساسية (Master Hash) المرجعية لكشف أي تغيير في الكود.

3
تنبيه المستخدم

إرسال تنبيه فوري للمستخدم عند اكتشاف أي تغيير على السيرفر.

مثال

أداة DirectoryMonitor تفحص كل مجلدات الويب تلقائيًا وتكتشف أي تغييرات في الكود وتنبّه المستخدم بإيميل عند اكتشافها.

كيفية الدفاع ضد DNS Hijacking

  1. اختيار Registrar معتمد من ICANN وتفعيل Registrar-Lock على اسم الدومين
  2. تأمين معلومات حساب المالك (Registrant)
  3. تضمين DNS Hijacking في خطط الاستجابة للحوادث واستمرارية الأعمال
  4. استخدام أدوات/خدمات مراقبة DNS لمتابعة عنوان IP الخاص بسيرفر DNS وضبط تنبيهات
  5. تجنّب تحميل Codecs صوتية وفيديو وأدوات تحميل أخرى من مواقع غير موثوقة
  6. تثبيت برنامج مكافحة فيروسات وتحديثه بانتظام
  7. تغيير كلمة مرور الراوتر الافتراضية اللي بتيجي من المصنِّع

الخلاصة العامة للموديول

الموديول ده ناقش بالتفصيل المفاهيم العامة لسيرفرات الويب، وأنواع التهديدات والهجمات المختلفة عليها، ومنهجية هجوم الـ Web Server (جمع المعلومات، الـ Footprinting، فحص الثغرات، كسر كلمات المرور)، وأدوات اختراق السيرفرات المتنوّعة. كذلك تطرّق للإجراءات المضادة اللي يقدر المدافعون يستخدموها لمنع محاولات الاختراق، واختتم بمناقشة تفصيلية لكيفية تأمين السيرفرات باستخدام أدوات حماية مختلفة.

$ cat ./module13_summary.txt
  • السيرفرات معرَّضة أكتر من غيرها لأنها لازم تكون متاحة من أي مكان على الإنترنت — عكس أنظمة داخلية ممكن تتحمي بسهولة بالـ Firewall وحده
  • أغلب الثغرات في Apache وIIS وNginx بترجع لتحقّق إدخال ناقص (Input Validation) — سواء في Headers أو Certificates أو استعلامات SQL
  • Directory Traversal وWeb Cache Poisoning وResponse Splitting كلها بتستغل ثقة السيرفر الزايدة في المدخلات أو المحتوى المخزَّن مؤقّتًا
  • منهجية الهجوم بتتدرّج من جمع معلومات سلبي (robots.txt، Banner Grabbing) لنشاط فعّال (Vulnerability Scanning، Password Cracking)
  • الدفاع الأساسي: Patching منتظم، تقليل البروتوكولات والخدمات المفتوحة، أقل صلاحيات ممكنة للحسابات، ومراقبة دورية لتغييرات الكود عبر Hash Comparison

السيرفر اللي مكشوف للعالم كله هو أول نقطة هجوم غالبًا، مش آخرها. من robots.txt لحد Directory Listing، كل تفصيلة صغيرة في الإعداد بتبني صورة للمهاجم عن بنية النظام قبل ما يوصل لأي ثغرة فعلية.

Exam Tip

أسئلة هذا الموديول غالبًا تُركِّز على: الفرق بين Document Root وServer Root وVirtual Document Tree، أنواع الـ Virtual Hosting، ترتيب خطوات منهجية هجوم الـ Web Server الستة، الفرق بين Directory Traversal وDirectory Brute Forcing، وآلية HTTP Response Splitting وWeb Cache Poisoning.
